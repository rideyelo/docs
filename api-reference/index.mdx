The endpoint pages in this tab are generated from `yelo-api`'s committed `openapi.json`. The same spec drives the Orval clients in `yelo-web` and `yelo-frontend`. See [OpenAPI and generated clients](/engineering/openapi-and-clients).

## Base URL

Production is `https://api.rideyelo.com`. There is no staging API. See [System overview](/engineering/overview) for environments.

## Authentication

| Caller | Credential | Details |
| --- | --- | --- |
| Mobile app and web sites | App JWT in `Authorization: Bearer` | [Authentication](/engineering/api/authentication) |
| Mid-sign-in clients | Auth v3 onboarding token | [Authentication](/engineering/api/authentication) |
| Dashboard (`/dashboard/*`) | Clerk session token | [Dashboard architecture](/engineering/web/dashboard-architecture) |

## Responses

Handlers return the standard success envelope, and handler errors use the standard error body. See [Request lifecycle](/engineering/api/request-lifecycle) for envelopes, status codes, and rate limits.

## Keep this reference current

The spec here is a copy. After `yelo-api` changes its spec, refresh the copy from a `yelo-api` checkout:

```bash
python3 scripts/sync-openapi.py ../yelo-api/openapi.json
```

The script sets the production server and keeps one display tag per operation, so each endpoint appears once in the sidebar.
