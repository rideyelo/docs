The **Global KPIs** page, opened from **KPI** in the sidebar, shows growth and activity across the whole Yelo network. For one market's live activity, use [Live operations](/dashboard/live). For one community's ride metrics, use **Rides** > **KPIs**. See [Rides](/dashboard/rides#kpis-tab).

For definitions of the ride metrics, see [Ride metrics](/dashboard/ride-metrics).

## Prerequisites

- An admin account. See [Dashboard roles and access](/administration/dashboard-roles).

## Dashboard home page

The dashboard home page sends you to a page for your role:

| Role | Home page |
| --- | --- |
| Admin | **Live** |
| Intern | **Community** |
| Fleet manager | **Fleet** |

Clicking **Yelo Dashboard** at the top of the sidebar opens the same page.

## Global KPIs

Click **KPI** in the sidebar to open **Global KPIs**. The page always covers all markets, so the sidebar shows **All markets** instead of the community selector. Test communities are excluded from every number. User, driver, and attender counts also exclude test users, but **GMV** and **Completed Rides** still include rides by test riders in real communities.

### Global metrics

Each card shows the all-time total. The change on each card compares what was added in the current calendar week (from Monday 00:00 UTC) with what was added in the previous full week.

| Card | All-time total |
| --- | --- |
| **Total Users** | Users with a completed profile. |
| **Total Drivers** | Users with an active driver application. |
| **GMV** | Sum of fares for completed rides, using the discounted price when one applies. |
| **Attenders** | Distinct users who joined at least one event. |
| **Completed Rides** | Completed rides that weren't canceled. |

<Note>
  Early in the week, the change compares a partial week with a full week, so it often shows a drop.
</Note>

### Weekly trends

Two charts show the last 12 weeks, one point per week. Click a metric above a chart to plot it.

| Chart | Metrics |
| --- | --- |
| **People** | **Users**, **Drivers**, and **Attenders** added each week. |
| **Activity** | **GMV** and **Rides** for each week. |

### Signup acquisition

The **Signup acquisition** card shows where new users found Yelo. It groups sources below 0.5% of signups into **Other / historical**. The center of the chart shows the number of signups in view and the share that has an attributed source.

Use the switches to change which signups are counted. Shares are recalculated when you exclude signups.

| Switch | Effect when off |
| --- | --- |
| **Historical** | Excludes older signups that were created before Yelo captured a source. |
| **No source / unmatched** | Excludes signups with no source or an unmatched source. |

If you see **Attribution backfill is running**, counts can change while older signups are classified.

### Next action queue

The **Next action queue** lists up to seven driver leads that need attention. Leads with pending review items come first, followed by the leads contacted longest ago or never contacted. Only leads in the new, application, pending approval, pending background check, and zero-drives stages appear.

| Column | Description |
| --- | --- |
| **Lead** | Lead name and source. Click it to open the lead on the **Drivers** page. |
| **Community** | The lead's community, or **Unassigned**. |
| **Next action** | The suggested step, such as **Make first contact**, **Follow up**, **Check background status**, or **Help schedule first drive**. |
| **Last contacted** | Date of the last message, or **Never contacted**. |
| **Priority** | **Review ready** when the lead has pending items, otherwise **Follow-up**. |

Click **Open leads** to go to the full pipeline. See [Driver leads](/dashboard/driver-leads).
