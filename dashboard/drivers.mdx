The **Drivers** page groups everything you need to onboard and manage drivers. Use it to find drivers in a community, see which applications need attention, and approve or reject each application requirement.

Open **Drivers** in the **Global** group of the sidebar. The page has five tabs:

| Tab | What it shows |
| --- | --- |
| **Pipeline** | A kanban board of driver leads. See [Driver leads pipeline](/dashboard/driver-leads). |
| **Next action queue** | Leads that need a review or a follow-up, in priority order. |
| **Referral payouts** | Drivers whose referral bonus needs review. |
| **Disqualified** | Leads removed from the active pipeline. |
| **Drivers** | The driver directory and application review queues. |

The tab you pick is saved in the URL as `?tab=`, so you can share a link to a specific tab. For admins, links that include `?userId=`, such as those in Slack alerts, open the **Drivers** tab with that driver's application already open.

## Prerequisites

- An `admin` or `intern` dashboard role to see every tab. Interns only see drivers and leads in their assigned community. See [Dashboard roles and access](/administration/dashboard-roles).
- An `admin` role to review applications. Only admins can approve or reject requirements, and only admins can view license photos.
- Fleet managers see only the **Drivers** tab, limited to the **Active Drivers** list for their fleets.

## Work the next action queue

The **Next action queue** tab lists open leads that need someone to act next. It includes leads in every active pipeline stage, from **New leads** through **0 drives**.

Yelo sorts the queue like this:

1. Leads with the most pending application items come first.
2. Leads you contacted longest ago come next. Leads that were never contacted sort before everyone else at the same level.

The queue uses the same search, tag, and community filters you set on the **Pipeline** tab.

| Column | Description |
| --- | --- |
| **Lead** | The lead's name, or phone number if there's no name, with the lead source underneath. |
| **Community** | The lead's community, or **Unassigned**. |
| **Next action** | The recommended next step. See the table below. |
| **Last contacted** | The date of the last correspondence, or **Never contacted**. |
| **Priority** | **Review ready** when the lead has pending items to review. Otherwise **Follow-up**. |

The **Next action** column shows one of these values:

| Next action | When it appears |
| --- | --- |
| **Review N pending item(s)** | The profile picture, license, vehicle, or Stripe step is pending. |
| **Check background status** | The lead is waiting for background clearance. |
| **Help schedule first drive** | The driver is approved but hasn't completed a drive. |
| **Follow up** | The lead has been contacted before and has nothing pending. |
| **Make first contact** | Nobody has contacted the lead yet. |

Select a lead's name to open the lead sheet. See [Review a lead](/dashboard/driver-leads#review-a-lead).

## Review referral payouts

The **Referral payouts** tab shows **Pending referral payouts**. Drivers enter this list after they complete their first drive.

| Column | Description |
| --- | --- |
| **Driver** | The driver's name. Select it to open the lead sheet. |
| **Community** | The driver's community, or **Unassigned**. |
| **Referral credit** | Who gets credit for the referral, or **Unassigned**. |
| **First drive** | Always **Completed** for drivers in this list. |
| **Bonus** | The referral bonus amount. |
| **Status** | **Needs review**. |

To change who gets referral credit, open the lead sheet and edit **Referral credit**. Only admins can edit it.

## Review disqualified leads

The **Disqualified** tab lists leads removed from the active pipeline. Each row keeps the lead's **Community**, the **Reason** entered when the lead was disqualified, and the lead **Source**. The full history stays in the lead's activity log.

To disqualify a lead, see [Disqualify a lead](/dashboard/driver-leads#disqualify-a-lead).

## Browse the driver directory

The **Drivers** tab shows drivers in the community selected in the sidebar. For admins, the selected community is saved in the page URL as `?community=`, so links such as **All drivers** on the [Live](/dashboard/live#monitor-drivers) page open the right market. Admins can turn on **Show all communities** to see drivers across every community, and then narrow the list with the **All Communities** filter.

Fleet managers with more than one fleet in the selected community see a **Fleet** selector instead.

### Driver metrics

The metric cards at the top summarize the current list:

| Metric | Description |
| --- | --- |
| **Total Drivers** | Drivers in the list. |
| **Approved Drivers** | Drivers whose application is approved. |
| **In Process** | Drivers with an application in progress. |
| **Inactive** | Drivers with a completed application who haven't been activated. Shown only with **Show all communities** on. |
| **Ready for Review** | Drivers with submitted requirements waiting for review. |
| **Avg. Rating** | The average rating across drivers who have a rating. Shows **N/A** when nobody is rated. |
| **Total Drives** | Completed drives across all listed drivers. |

### Driver lists

The **Drivers** tab has its own set of lists:

<Tabs>
  <Tab title="Active Drivers">
    The **Driver Directory** lists drivers with these sortable columns: **Name**, **Drives**, **Cancels (Driver+Rider)**, **Rating**, and **Last Active**. It also shows a **Community** column when **Show all communities** is on, and a **Status** column of **Approved** or **Pending** when you view a single community.

    Admins can select a row to open the driver's application.
  </Tab>
  <Tab title="In Process">
    **In Process Applications** lists drivers who have started but not finished their application. The **Progress** column shows how many of the four required steps are complete, such as `2/4`. The **Profile**, **License**, **Stripe**, and **Vehicle** columns show each step's status.

    Only admins see this list.
  </Tab>
  <Tab title="Ready for Review">
    **Ready for Review** lists drivers with submitted requirements that need a decision. It shows the **Submission Date** and the status of each step. Select **Review** to open the application.

    Only admins see this list.
  </Tab>
  <Tab title="Inactive">
    **Inactive Drivers** lists drivers with completed applications that have not been activated. It shows **Name**, **Email**, **Community**, **Vehicles**, and **Submitted**. Select a row to open the application.

    Only admins see this list, and only with **Show all communities** on.
  </Tab>
</Tabs>

Each application step shows one of these statuses:

| Status | Meaning |
| --- | --- |
| **Complete** | The step is approved. |
| **Pending** | The driver submitted the step, and it needs review. |
| **Rejected** | A reviewer rejected the step. The driver sees the rejection reason. |
| **Restricted** | Stripe has restricted the driver's connected account. |
| **Not Applied** | The driver hasn't submitted this step yet. |

## Review a driver application

The **Review Driver Application** sheet shows every requirement for one driver, with the driver's name, email, and phone number at the top. Click the phone number to copy it.

<Steps>
  <Step title="Open the application">
    Select **Review** on the **In Process** or **Ready for Review** list, or select a driver row in the directory. You can also open it from the **Fleet Driver Directory** on the **Fleet** page.
  </Step>
  <Step title="Check each requirement">
    Review the sections in order. Click any photo to see it full size.

    | Section | What you see |
    | --- | --- |
    | **Profile Picture** | The driver's profile photo. |
    | **Driver's License** | The **Front** and **Back** license photos. Interns see "License information review is restricted to administrators." instead. |
    | **Stripe Account** | The **Account ID**, **Merchant Name**, and **Stripe Verification Status**, including **Payouts Enabled** and any errors, currently due items, or past due items. |
    | **Vehicles** | Each submitted vehicle with its ownership, approval, and default badges. A **Provided by fleet** badge appears when the driver's fleet supplies the vehicle. |
  </Step>
  <Step title="Approve or reject">
    When a step is **Pending** or **Rejected**, select **Approve** or **Reject** for it.

    To reject, enter a reason in the **Reject Requirement** dialog and select **Submit Rejection**. The reason is required, and the driver sees it in the app.
  </Step>
</Steps>

When you approve a step that wasn't already complete, Yelo sends the driver a push notification titled "You're approved!" that links to their application status. Approving a step that is already complete doesn't send another notification.

<Note>
  Stripe keeps the **Stripe Account** step up to date automatically. The sheet can show **Approve** and **Reject** for a pending Stripe step, but Yelo rejects manual Stripe reviews. Ask the driver to finish their Stripe requirements instead.
</Note>

Fleet vehicles don't show **Approve** or **Reject** in the sheet. An approved fleet default vehicle completes the vehicle step for every fleet member. See [Default vehicles and approval](/dashboard/fleet-vehicles#default-vehicles-and-approval).

After all requirements are approved and the background check clears, activate the driver from the lead sheet. See [Activate a driver](/dashboard/driver-leads#activate-a-driver). For the full onboarding flow, see [Driver onboarding](/concepts/driver-onboarding).
