The user directory lists every Yelo rider and driver in the dashboard. Use it to look up an account, check recent activity, review contacts and messages, and correct profile details.

Open it from **Users** in the sidebar. You can also open any user from the global search in the top bar.

## Prerequisites

- An `admin` or `intern` dashboard role. Interns see users in their assigned community only.
- An `admin` role to open the user detail sheet. Interns can browse and search the directory, but selecting a row doesn't open anything. Searching all users from the global search is also admin-only.

## Find a user

### Global search

Select **Search…** in the top bar, or press <kbd>Cmd</kbd>+<kbd>K</kbd> (<kbd>Ctrl</kbd>+<kbd>K</kbd> on Windows). The search finds pages, settings, communities, fleets, and users.

For admins, Yelo searches every user after you stop typing. It returns up to 15 users matched by name, phone number, or user ID. Interns see only users already loaded from their community's directory.

Use the arrow keys to choose a result and <kbd>Enter</kbd> to open it. Selecting a user opens their detail sheet in the directory.

### Directory search

On the **Users** page, type in **Search any name, phone, email, or ID…**. The search matches:

- **Name**. Every word you type must match the first or last name, in any order.
- **Phone number** and **email**, as a partial match.
- **User ID**, as an exact UUID match.

Name search tolerates typos. Words of 4 to 24 characters also match names that differ by one letter: a missing, extra, or wrong letter, or two swapped adjacent letters. Shorter words must appear exactly. For example, `jonh smtih` finds John Smith.

Searches are limited to 256 bytes and 8 words. Longer searches return an error instead of dropping words.

<Tip>
  To find a ride by its ID, use the search on the **Rides** page. It matches the rider name, driver name, or ride ID.
</Tip>

### Filter the directory

- **Account type** buttons filter by **All**, **Student**, **Community**, **Driver**, **Test**, or **Banned**.
- **All tags** filters by one tag. The directory shows all tags by default. The list includes every tag used in the selected community, including automatic fleet tags. Select **Clear *tag* filter** to show all users again.
- **All Communities** limits the directory to one community.

The selected tag is saved in the page URL as `?tag=`, so you can share a filtered view.

### Last active

The **Last Active** column shows the most recent of these:

- The user's latest heartbeat or location update
- Device telemetry from the Yelo app
- Driver activity

If none exist, Yelo uses the signup date. Background app activity counts, so a recent date doesn't guarantee the user opened the app. Hover over the date to see the exact time. Sort by **Last Active** to find recently active or dormant users.

## Review a user

Admins can select a row to open the user detail sheet. The sheet shows:

- **Tags**. See [Tags](#tags).
- **Profile**, with school, community, home community, graduation year, join date, and last active time.
- **Fleet membership**, where admins edit the fleets a driver belongs to. See [Manage fleet memberships](#manage-fleet-memberships).
- **Driver Info** for drivers, including the payout fleet, active fleet, rating, drives, and cancels.
- **Driver fleet enrollment**, where admins assign a payout-ready fleet.
- **Operations**, with the **Test account** toggle, user ID, app version, and device.
- **Contacts & friends**. See [Registered contacts](#registered-contacts).
- **Quo · recent contact**. See [Quo messages](#quo-messages).
- **Recent Notifications**, **Ride History**, and **Drive History**.

Ride and drive counts include completed rides that are still waiting for the rider's rating. A driver's cancels include rides the driver canceled and rides Yelo requeued to another driver after this driver canceled. Those rides also appear in **Drive History** as **Cancelled by driver**, even though another driver may have completed them.

### Registered contacts

**Contacts & friends** lists the user's friends and their **Registered contacts · not friends**. These are people in the user's uploaded phone contacts who have a Yelo account but aren't friends with the user yet. Select a contact to open their detail sheet.

For details on contact uploads and matching, see [Contact sync](/administration/contact-sync).

### Quo messages

Admins see the latest texts with the user across Yelo's Quo numbers. Select **Quo** under the phone number to open the contact in Quo. If the user has no Quo contact, the panel shows **No linked Quo contact yet.**

The Quo panel works the same way as in the [driver leads pipeline](/dashboard/driver-leads#quo-messages).

## Edit a profile

Admins can correct a user's name, phone number, and communities.

<Steps>
  <Step title="Open the user">
    Open the user's detail sheet and select **Edit profile**.
  </Step>
  <Step title="Update the fields">
    Edit any of these fields:

    - **First name** (required, up to 100 characters)
    - **Last name** (up to 100 characters)
    - **Phone number** (required). Yelo normalizes the number when saving.
    - **Active community**: the community the user is currently using.
    - **Home community**: the user's permanent home community.
  </Step>
  <Step title="Save">
    Select **Save profile**. Yelo shows **Profile updated** and refreshes the directory and search results.
  </Step>
</Steps>

Yelo rejects the change when:

- The phone number belongs to another account or lead. The error reads "This phone number is already assigned to an account or lead."
- The user or a selected community is no longer available.

## Manage fleet memberships

A driver can belong to more than one fleet. One of those fleets is the active fleet, which the driver drives for and which receives payouts.

<Steps>
  <Step title="Open the membership editor">
    Open the user's detail sheet and expand **Fleet membership**. **Enrolled fleets** lists the driver's current fleets. Archived fleets show an **Archived** badge.
  </Step>
  <Step title="Change memberships">
    Search in **Find a fleet to add…** and select a fleet to add it. Select the remove icon on a fleet to revoke that membership, or **Undo removal** to keep it. Select the radio button next to a fleet to make it the active fleet.
  </Step>
  <Step title="Review and confirm">
    Select **Review membership changes**. The **Save fleet membership changes?** dialog lists each added membership, each revoked membership, and any change to the active fleet. Select **Confirm changes**.
  </Step>
</Steps>

Saving takes the driver offline. Yelo blocks the change while the driver has an active ride. Revoking a membership also removes the driver's access to that fleet's vehicles. The driver's community doesn't change. If someone else changed the memberships while you were editing, select **Reload latest memberships** and make your changes again.

To enroll a driver in a fleet that manages payouts, expand **Driver fleet enrollment**, select a payout-ready fleet, and select **Assign active payout fleet**. Yelo creates or updates the driver application, marks fleet-managed payouts complete, and makes that fleet active. The driver activates automatically after the remaining setup items are complete.

## Tags

Tags label users for filtering and follow-up. Driver leads use the same tags.

Admins add tags in the **Tags** field of the detail sheet. Type in **Add a tag...** to add one, or select the remove icon on a tag to delete it. Tags are free-form, and the tag filter ignores capitalization.

### Automatic fleet tags

Yelo adds a `Fleet: <fleet name>` tag to each driver who meets both conditions:

- The driver is an active member of a fleet that hasn't been deleted.
- The driver's own driver application is activated.

A driver can join a fleet before their application is activated. That driver keeps their fleet membership, but Yelo doesn't show the tag until you [activate the driver](/dashboard/driver-leads#activate-a-driver). Drivers whose application is pending or deactivated don't get the tag.

Yelo calculates fleet tags each time it loads the directory, so they always reflect current data:

- When a driver joins, leaves, or switches fleets, their tag updates automatically.
- When a fleet is renamed, its tag uses the new name.
- You can't remove a fleet tag from the detail sheet. Remove the driver from the fleet instead.

Manual tags stay separate from fleet tags. A manually added tag that starts with `Fleet: ` only appears while the user qualifies for that fleet's automatic tag.

To list all active drivers in a fleet, select the fleet's tag in **All tags**.
