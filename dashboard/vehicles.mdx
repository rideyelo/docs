title: "Vehicle types"
description: "Add, edit, and deactivate the vehicle types that fleets, vehicles, pricing, and the rider app use across every Yelo community."
---

Vehicle types are Yelo's global catalog of vehicle categories, such as a car or a cart. Fleets choose which types they support, each vehicle belongs to one type, and pricing configs are set per type. The same catalog is served to the rider and driver apps in every community.

You manage the catalog in the **Vehicle Types** section of **Fleet Management**. The old **Vehicles** page URL, `/vehicles`, redirects there.

## Prerequisites

- An `admin` dashboard role. Only admins can create, edit, or deactivate vehicle types. See [Dashboard roles and access](/administration/dashboard-roles).

## Open the vehicle type catalog

1. Open **Fleets** in the **Configuration** group of the sidebar.
2. Select the **Vehicles** tab.

The **Vehicle Types** table sits above the vehicle inventory. It lists every type, including inactive ones, in sort order.

| Column | Description |
| --- | --- |
| **Display Name** | The name people see. |
| **Slug** | The type's permanent identifier. |
| **Icon** | The icon key. Golf carts show as `cart`. |
| **Seats** | The allowed seat range, such as `4–6`. |
| **Sort Order** | The type's position in the catalog. Yelo lists types from the lowest number to the highest. |
| **Status** | **Active** or **Inactive**. |

To manage vehicles themselves, see [Fleet vehicles](/dashboard/fleet-vehicles).

## Add a vehicle type

<Steps>
  <Step title="Open the form">
    Select **Add Vehicle Type**.
  </Step>
  <Step title="Enter the details">
    Fill in the fields in [Vehicle type fields](#vehicle-type-fields). **Slug** and **Display Name** are required.
  </Step>
  <Step title="Save">
    Select **Add Vehicle Type**.
  </Step>
</Steps>

## Edit a vehicle type

Select a row, or select **Edit** on it. Update the fields and select **Save Changes**.

You can't change a type's **Slug** after you create it.

### Vehicle type fields

| Field | Required | Description |
| --- | --- | --- |
| **Slug** | Yes | A permanent identifier, such as `cart`. |
| **Display Name** | Yes | The name shown in the dashboard and apps, such as `Cart`. |
| **Description** | No | A short description of the vehicle. |
| **Icon** | Yes | The icon the apps use: **Car**, **Big car**, **Cart**, or **Minibus**. |
| **Vehicle artwork** | No | The artwork riders see for this type. See [Vehicle artwork](/dashboard/fleet-vehicles#vehicle-artwork). |
| **Min Seats** | No | The fewest seats a vehicle of this type can have. Must be zero or greater. |
| **Max Seats** | No | The most seats a vehicle of this type can have. Must be greater than or equal to **Min Seats**. |
| **Sort Order** | No | The type's position in the catalog. |
| **Active** | No | Whether a new type is available. Inactive types are hidden from users and dropdowns. The API ignores this toggle when you edit an existing type. |

## Deactivate a vehicle type

Select **Deactivate** on an active type's row. The dashboard deactivates it right away, without a confirmation step.

Deactivated types disappear from the apps and from vehicle type dropdowns in the dashboard. The dashboard can't reactivate a type. Turning **Active** back on and saving has no effect, because the update endpoint doesn't write `is_active`. Ask engineering to reactivate it in the database.

<Warning>
  Vehicles need an active type. If a vehicle's saved type is inactive, you must choose an active type before you can save changes to that vehicle. Check which fleets and pricing configs use a type before you deactivate it.
</Warning>

For how vehicle types affect fares, see [Pricing](/concepts/pricing).
