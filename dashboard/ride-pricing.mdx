The **Pricing Management** page in the dashboard controls how Yelo quotes rides in each community. Use it to review a community's service area and pricing zones, create pricing configs for each fleet and vehicle type, choose how fares are adjusted, and set what riders see for each ride option. The **Parity** tab compares your fares with Uber and Lyft quotes in the same market.

## Prerequisites

- A dashboard account with access to the communities you want to price. See [Dashboard roles and access](/administration/dashboard-roles).
- A platform admin account to edit pricing zones or change global jitter settings.
- A bounding box on the community to use the pricing geography map.

## Select a community

The page opens on a map of active community service areas.

1. Click a community boundary on the **Community service areas** map.
2. Alternatively, select a row in the **Communities** table below the map. Use the filter box to search by community, fleet, or vehicle.

The selected community opens in the pricing workspace. The workspace shows the community's pricing configs, the pricing geography map, and recent pricing activity.

## Work with pricing geography

The **Pricing geography** map compares the community's service boundary and pricing zones with the paths riders actually requested. Use it to check whether zones cover real demand before you change pricing.

Open the layer panel on the map to toggle these layers:

| Layer | What it shows |
| --- | --- |
| **Zones** | The community's pricing zones. |
| **Bounding box** | The community's service boundary. |
| **Ride routes** | Quoted routes from recent ride requests in the community. |

When **Ride routes** is on, pick a time window of **7d**, **14d**, **30d**, or **60d**. Routes appear in two colors:

- **Requested route** (blue): a route a rider requested.
- **Pricing decline** (red): a request where a driver declined because of the fare or payout.

The panel shows how many routes are on the map. When a window has more than 2,000 routes, the map shows only the newest 2,000.

### Edit zones inline

Platform admins can manage zones next to the map in the **Zone editor** panel. Other users see the map but can't edit zones.

- **Add a zone**: Draw a shape with the polygon control on the map. Then enter the zone details in the **New zone** dialog.
- **Edit a zone**: Select the zone in the **Zone editor** panel to open the **Edit zone** dialog.
- **Delete a zone**: Remove the zone from the **Zone editor** panel.

Each zone has a name, description, color, priority, an active toggle, and a toggle to show the zone on the rider map.

## Create or edit a pricing config

A pricing config sets the fare for one fleet and vehicle type in a community.

1. Click **Add pricing config**. To change an existing config, open it from the community's pricing table.
2. Select the **Community**, **Fleet**, and **Vehicle type**. You can't change these after you create the config.
3. Choose a **Pricing type**. See [Pricing types](#pricing-types).
4. Choose a **Fare adjustment**. See [Fare adjustment modes](#fare-adjustment-modes).
5. Enter the **Base price ($)** and **Price per minute ($)**, and add any distance tiers. See [Distance tiers](#distance-tiers).
6. Optionally set the rider-facing **Rider title** and **Vehicle artwork**. See [Rider-facing ride options](#rider-facing-ride-options).
7. Turn on **Always shown** to show this ride option even when no matching driver is online.
8. Save the config.

When you edit a config, turn off **Enabled** to retire it. Yelo keeps the config's history.

### Pricing types

| Pricing type | Description | Default fare adjustment |
| --- | --- | --- |
| **Per ride** | One fare for the whole ride. | Jitter |
| **Per person** | A fare for each rider. | Round up |

When you change the pricing type, the dashboard resets **Fare adjustment** to that type's default. You can then pick a different mode.

<Warning>
  Rider quotes and confirmed fares only load **Per ride** configs (`ListActiveRidePriceParameters` in `queries/community.sql`). A **Per person** config saves and shows in the dashboard, but riders never see it and it never prices a ride.
</Warning>

## Distance tiers

The **Distance tiers** table in the config form sets the per-mile rate for each stretch of a ride. A new config starts with one open-ended tier from 0 miles at $1.50 per mile.

| Column | Description |
| --- | --- |
| **#** | The tier's position. |
| **From (mi)** | Where the tier starts. You can't edit it. The dashboard sets it to the previous tier's **Up to (mi)** value, and to `0.00` for the first tier. |
| **Up to (mi)** | Where the tier ends. The last tier shows **∞** because it has no upper limit. |
| **$/mi** | The price per mile inside the tier. |

To change the tiers:

- **Add a tier**: Click **+ Add tier**. The dashboard closes the current last tier one mile after its start and adds a new open-ended tier with the same rate. Then edit **Up to (mi)** and **$/mi**.
- **Remove a tier**: Click the trash icon on the row. Removing the last tier makes the tier before it open-ended. Removing any other tier extends the next tier down to cover its range. You can't remove the only tier.

The dashboard checks the tiers as you type and shows the first problem below the table. **Save** stays disabled until you fix it.

| Rule | Message |
| --- | --- |
| A config has at least one tier. | "Pricing config must include at least one tier." |
| The first tier starts at 0 miles. | "First tier must start at 0 miles." |
| No tier has a negative **$/mi**. | "Tier N has a negative price per mile." |
| Every tier except the last has an **Up to (mi)** value. | "Only the last tier may be open-ended." |
| The last tier has no **Up to (mi)** value. | "Last tier must be open-ended (leave Up to blank)." |
| **Up to (mi)** is greater than **From (mi)**. | "Tier N: Up to must be greater than From." |
| Tiers don't leave a gap or overlap. | "Tier N: gap between tier N-1 and tier N." or "Tier N: overlap between tier N-1 and tier N." |

The API runs the same checks when you save. See [Validation](/engineering/domains/pricing-configuration#validation). For how tiers feed into a fare, see [Pricing](/concepts/pricing#the-pricing-model).

## Preview a config

The **Live preview** section at the bottom of the config form quotes three fixed trips with the values currently in the form. Nothing is saved until you click **Save**.

| Card | Trip |
| --- | --- |
| **Short** | 1 mi · 3 min |
| **Average** | 3 mi · 9 min |
| **Long** | 6 mi · 18 min |

Each card shows the price the rider pays. When the "was" price is different, hover over the amount to see it as **Strikethrough**.

The preview needs a selected **Community**. It refreshes about 300 ms after you stop changing the community, base price, per-minute price, tiers, or fare adjustment. It uses the community's current surge multiplier.

- If the tiers or fare adjustment are invalid, the section shows "Fix errors above to see preview."
- If the request fails, the section shows "Failed to compute preview:" followed by the error.

The preview ignores pricing zones and discounts. See [Preview quotes](/engineering/domains/pricing-configuration#preview-quotes) and [Dashboard previews](/concepts/pricing#dashboard-previews).

## Fare adjustment modes

The fare adjustment controls how Yelo turns the calculated fare into the price the rider sees.

| Mode | Dashboard label | Behavior |
| --- | --- | --- |
| `jitter` | **Jitter** | Adds a small random amount to the fare and shows a higher "was" price next to it. Uses the [global jitter settings](#global-jitter-settings). |
| `rounded` | **Round up** | Rounds the fare up to the next whole dollar. For example, $12.10 becomes $13.00. |
| `none` | **None** | Charges the calculated fare, truncated to whole cents, with no adjustment. |

With **Round up** and **None**, Yelo doesn't show an inflated "was" price.

With **Round up**, Yelo applies discounts to the calculated fare first and then rounds the discounted fare up to a whole dollar. Riders always see a whole-dollar price.

Configs saved without a mode use `jitter`. Fallback fares for communities with no pricing config also use jitter.

If you manage pricing through the dashboard API, set the mode in the `adjustment` object on a price parameter:

```json
{
  "pricing_type": "per_person",
  "base_price": 4,
  "price_per_minute": 0.25,
  "adjustment": {
    "mode": "rounded"
  }
}
```

The API returns `400` if `mode` isn't `jitter`, `rounded`, or `none`.

## Global jitter settings

Jitter settings are shared by every pricing config that uses the **Jitter** mode, across all communities. Only platform admins can view or change them.

To change them, click **Global jitter settings** at the top of the **Pricing Management** page, update the values, and click **Save global settings**.

| Setting | API field | Default | Description |
| --- | --- | --- | --- |
| **Minimum added ($)** | `min` | `0.50` | Smallest random amount added to the fare. |
| **Maximum added ($)** | `max` | `1.00` | Largest random amount added to the fare. |
| **Dollar crossing threshold ($)** | `clamp_overshoot_limit` | `0.20` | If jitter pushes the fare into the next dollar by less than this amount, Yelo keeps the fare in the original dollar instead. |
| **Clamp range minimum ($)** | `clamp_range_min` | `0.90` | Lowest cents value used when Yelo keeps the fare in the original dollar. |
| **Clamp range maximum ($)** | `clamp_range_max` | `0.99` | Highest cents value used when Yelo keeps the fare in the original dollar. |
| **Minimum "was" price multiplier** | `anchor_inflation_min` | `1.15` | Smallest multiplier for the "was" price shown next to the fare. |
| **Maximum "was" price multiplier** | `anchor_inflation_max` | `1.30` | Largest multiplier for the "was" price shown next to the fare. |

For example, with the defaults, a calculated fare of $11.60 might get $0.50 added, which gives $12.10. That crosses into the next dollar by only $0.10, so Yelo keeps the fare between $11.90 and $11.99.

Values must meet these rules, or Yelo rejects the save with a `400`:

- All values are zero or greater.
- Each minimum is less than or equal to its maximum.
- **Clamp range maximum** is less than `1`.
- **Dollar crossing threshold** is at most `1`.
- **Minimum "was" price multiplier** is at least `1`.

Platform admins can also read and replace these settings with `GET` and `PUT` requests to `/dashboard/pricing/jitter`. A `PUT` replaces all values, so send every field:

```json
{
  "min": 0.5,
  "max": 1,
  "clamp_overshoot_limit": 0.2,
  "clamp_range_min": 0.9,
  "clamp_range_max": 0.99,
  "anchor_inflation_min": 1.15,
  "anchor_inflation_max": 1.3
}
```

Other users get a `403`.

## Rider-facing ride options

Each pricing config can control how its ride option looks in the rider app.

| Field | API field | Limit | Behavior when blank |
| --- | --- | --- | --- |
| **Rider title** | `display_name` | 80 characters | Uses the fleet and vehicle name. |
| **Vehicle artwork** | `image_asset` | 96 characters | Uses the vehicle type's default artwork. |

**Vehicle artwork** lists the image files bundled with the published iOS and Android rider apps, such as `cart.png`. Pick a file to preview it. If a config uses a file that the current apps no longer include, the dashboard shows it as not currently offered.

For example, to show a "Downtown Shuttle" option with shuttle artwork:

```json
{
  "display_name": "Downtown Shuttle",
  "image_asset": "shuttle.png"
}
```

## Compare quotes in the configs table

The selected community's workspace lists its live pricing configs in a table. Use the quote columns to compare ride options without opening each config.

| Column | Description |
| --- | --- |
| **Fleet** | The fleet the config belongs to. |
| **Vehicle** | The vehicle type. |
| **Rider option** | The rider title and artwork file. Shows **Default** and **Default image** when they're blank. |
| **Pricing** | **per ride** or **per person**. |
| **Base** | The base price. |
| **$/min** | The price per minute. |
| **Tiers** | The number of distance tiers. Click the number to see each tier's range and per-mile rate. |
| **Short (1mi)** | The quote for a 1-mile, 3-minute trip. |
| **Avg (3mi)** | The quote for a 3-mile, 9-minute trip. |
| **Long (6mi)** | The quote for a 6-mile, 18-minute trip. |
| **Featured** | Shows **Always shown** when the option appears even with no matching driver online. |
| **Status** | **Active** or **Inactive**. |

Each quote shows the price the rider pays. When the "was" price is different, hover over the amount to see it as **Strikethrough**. The dashboard hides the three quote columns when no config in the table has quotes.

You can't sort the table. `PricingConfigsTable.tsx` keeps sorting state, but the column headings have no click handler.

The header above the table shows the community's surge multiplier, the number of configs, and **Avg ride**. **Avg ride** is the lowest and highest **Avg (3mi)** quote across the community's configs, or one amount when they match.

Click a row, or its pencil icon, to open **Edit pricing config**. For how the API computes these quotes, see [Overview quotes](/engineering/domains/pricing-configuration#overview-quotes).

## View history or delete a config

### View history

1. In the configs table, click the **More** (three dots) button on the config's row.
2. Click **View history**.

The **Pricing config history** dialog lists earlier versions for the same fleet, vehicle type, and pricing type.

| Column | Description |
| --- | --- |
| **Effective dates** | When the version started and ended. A version with no end shows "no end date". |
| **Rider option** | The rider title and artwork file. Shows **Default title** and **Default image** when they're blank. |
| **Base** | The base price. |
| **$/min** | The price per minute. |
| **Tiers** | Each tier's range and per-mile rate. |

The history doesn't include the live version shown in the table. It lists versions that have ended, versions that haven't started yet, and versions for a fleet that no longer has an active service in the community (`ListDashboardRidePriceParameterHistory` in `queries/community.sql`). The dialog shows "No history for this config." when there are none.

Yelo adds a version each time you save an edit. See [Config versioning](/engineering/domains/pricing-configuration#config-versioning).

### Delete a config

1. In the configs table, click the trash icon on the config's row.
2. In the **Delete pricing config?** dialog, click **Delete**.

Deleting deactivates the config. It doesn't erase it. The config leaves the table and its versions stay in the history. This is the same action as turning off **Enabled** in the config form.

<Warning>
  Riders fall back to whichever config remains active. A community with no pricing config uses fallback fares. See [Fallback pricing](/concepts/pricing#fallback-pricing).
</Warning>

If the delete fails, the dialog stays open so you can retry.

## Review recent real-world pricing

The **Recent real-world pricing** card sits below the configs for the selected community. It shows the 12 most recently requested rides, so you can compare your configs with what riders were actually quoted and charged.

Three metrics summarize those rides:

| Metric | Description |
| --- | --- |
| **Average charged** | The average price charged across the listed rides. It uses the discounted price when a ride has one. |
| **Recent rides** | The number of rides listed. |
| **Price-related declines** | Driver declines with a price-related reason, out of all declines on the listed rides. **Top** shows the most common price-related reason. |

A decline counts as price-related when its reason mentions words such as "price", "pricing", "fare", "pay", "payout", "too low", "too high", "not enough", "expensive", or "cheap".

The table has one row per ride:

| Column | Description |
| --- | --- |
| **When** | When the rider requested the ride. |
| **Real ride** | The pickup and destination names. |
| **Option** | The fleet and vehicle type. Shows **Unassigned** when the ride has no fleet. |
| **Trip** | The trip distance in miles and estimated duration in minutes. |
| **Quoted** | The price quoted for the ride's vehicle type and fleet, taken from the ride's most recent `price_calculated` timeline event. When the charged price is different, it appears below as "charged". When the timeline has no matching quote, the column shows the charged price. |
| **Declines** | The number of driver declines, and how many were price-related. The badge is red when at least one was price-related. Hover over it to read the price-related reasons. |
| **Status** | The ride's current status. |

Click a row to open **Ride Details** with the route, zones, and full event history. See [Open ride details](/dashboard/rides#open-ride-details).

The card shows "No recent rides for this community." when the community has no rides.

<Note>
  `RecentPricingActivity.tsx` hides decline data and ride details from non-admins, and shows **Admin only** in **Price-related declines**. You can't reach that state today, because only admins can open **Pricing Management** (`ProtectedRoute` in `src/sites/dashboard/App.tsx`).
</Note>

## Zone pricing overrides and backtest

A zone override changes a fleet's rates inside one pricing zone. The backtest shows what the current overrides would have done to recent rides. Both appear below the configs table. For how zones change a fare, see [Pricing zones](/concepts/pricing#pricing-zones).

### Set a zone override

The **Zone pricing overrides** section lists each zone in the community. Under each zone, there's one row for each fleet that has a pricing config in the community.

1. Find the zone, then the fleet's row.
2. Enter any of the three values:

   | Field | Effect |
   | --- | --- |
   | **$/mi** | Replaces the tier rates for miles driven inside the zone. Enter `0` for a free zone. |
   | **$/min** | Replaces the config's per-minute rate inside the zone. |
   | **flat $** | Charged once when the route enters the zone. |

3. Click **Save**. **Save** is disabled until you change a value in the row.

Leave a field blank to inherit the fleet's config. The dashboard also treats a non-numeric entry as blank. Saving replaces all three values, so a blank field clears any value saved earlier. The API rejects negative values, and the dashboard shows "Failed to save zone pricing".

To remove an override, click **Clear** on its row. **Clear** only appears on rows that have a saved override.

The section shows a message instead of the rows in two cases:

- "No zones for this community. Draw zones on the map to set zone pricing." See [Edit zones inline](#edit-zones-inline).
- "No fleets configured for this community." Add a pricing config for the fleet first.

### Run a backtest

The **Pricing backtest** section re-prices recent completed rides with the current zone overrides.

1. Save the zone overrides you want to test.
2. Click **Run backtest**.

The dashboard requests up to 100 rides. Rides without a matching pricing config are left out. Simulated prices exclude surge and jitter, so the difference between the two simulated columns is the effect of the zones alone.

| Column | Description |
| --- | --- |
| **Route** | The pickup and destination names. |
| **Fleet** | The fleet that served the ride. |
| **Vehicle** | The vehicle type. |
| **Distance** | The ride distance in miles. |
| **Charged** | What the rider was charged. |
| **Sim (no zones)** | The simulated price with no zone overrides. |
| **Sim (zoned)** | The simulated price with the current zone overrides. |
| **Zone Δ** | **Sim (zoned)** minus **Sim (no zones)**. Green means the zones lower the fare. Red means they raise it. |

The footer row shows the number of rides, the total of each simulated column, and the total difference.

Click a row to open a dialog with the ride's distance, **Charged**, **Zoned**, and **Δ** values, and a map of the route over the community's zones.

If no rides qualify, the section shows "No completed rides with a matching price config to backtest."

<Warning>
  After the first run, the button reads **Re-run**, but clicking it doesn't request new results. It sets the same state that **Run backtest** already set (`ZonePricingBacktest.tsx`). To backtest again after you change an override, reload the page and click **Run backtest**.
</Warning>

For the ride selection and simulation rules, see [Zone backtest](/engineering/domains/pricing-configuration#zone-backtest) and [Zone pricing overrides](/engineering/domains/pricing-configuration#zone-pricing-overrides).

## Check competitor parity

The **Parity** tab compares Yelo fares in the selected community with the Uber and Lyft quotes riders saw in Fare Finder for the same trips. Use it to check whether your pricing sits inside the community's target range before you change a config.

Open it with the **Parity** tab next to **Configs** at the top of **Pricing Management**, or go to `/pricing?tab=parity`. The tab uses the community selected on the page.

Every comparison is a ratio: the Yelo fare divided by the competitor fare for the same trip, with surge removed from the competitor fare. The tab shows ratios as percentages. 100% is price parity. Below 100% means Yelo is cheaper.

### Choose the comparison

Use the controls in the tab header:

| Control | What it does |
| --- | --- |
| **vs Uber** / **vs Lyft** | The reference provider. Defaults to Uber. |
| **Standard** / **XL** / **Comfort** | The reference product class. Defaults to Standard. Yelo fares come from the community's `x` config for Standard and its `xl` config for XL. No Yelo config maps to Comfort, so that class shows competitor quotes without ratios. |
| Period | The quote window. Choose from **Last hour** through **Last 6 months**, or **All time**. Defaults to **Last 30 days**. |
| **Target** | The community's parity window. See [Set the parity window](#set-the-parity-window). |

The status chip next to the title summarizes the result:

| Status | Meaning |
| --- | --- |
| **Inside band** | Every trip-length band with enough data sits inside the target window. |
| **Below band** | At least one band is below the window, so Yelo is cheaper than the target. |
| **Above band** | At least one band is above the window and none is below, so Yelo is more expensive than the target. |
| **Thin data** | Neither a band nor the pooled ratio has enough quotes to score yet. |

A band needs at least 5 quotes to count. Until any band reaches 5, the pooled **All trips** ratio drives the chip once it has at least 3 quotes. The chip also names the band that put it out of range, or the pooled ratio and sample count.

The **Data so far** line shows how many quotes, quote passes, and long trips are in the period, and the spread of trip distances. When more data would unlock a better rate card fit, it says what's needed.

### Set the parity window

Each community has its own target window. New communities start at 80–95%.

1. Click **Target** in the tab header.
2. Enter **Min %** and **Max %**. Both must be between 50% and 150%, and **Min %** must be lower than **Max %**.
3. Click **Save**.

The window is saved on the community and applies to everyone who opens the tab.

### Read the bands and chart

The band tiles show the median ratio for each trip length:

| Band | Trip distance | Preset trip |
| --- | --- | --- |
| **All trips** | Every quote | |
| **Short** | Under 2 mi | 1 mi |
| **Average** | 2 mi to under 4.5 mi | 3 mi |
| **Long** | 4.5 mi and over | 6 mi |

**Fares by trip length** plots competitor fares with surge removed, a line for each active Yelo config, and the target window shaded around the reference provider's rate card. Dots are colored by provider. Use the dropdowns above the chart to show one pricing config or one provider. When more than 800 quotes match, the chart shows the newest 800.

### Use rate cards and suggestions

**Reference rate cards** lists the base, per-mile, and per-minute rates for each provider and class, next to the current Yelo config.

- Lyft publishes its rate card in each quote, so its row reads **Provider card**.
- Uber's card starts as Lyft's card scaled to Uber's fares on shared quote passes (**Scaled from Lyft**). It switches to a direct **Fit** once quotes span enough distance.
- **Too few** means there isn't enough data to fit a card yet. The row shows an effective per-mile rate only.
- **Fit error** is the typical dollar miss per quote.

**Match market** suggests rates that target the midpoint of the window against the reference provider and class. It compares current and suggested base price, per-mile, and per-minute rates, and the expected ratio at each band's preset trip.

- **Apply suggestion** opens the community's Standard (`x`) config in the editor with the suggested base price, per-minute rate, and a single per-mile tier.
- **Keep tiers, scale rates** opens the same config with every rate multiplied by one factor, so your distance tiers keep their shape.

Neither button saves anything. Review the config in the editor and save it yourself.

<Warning>
  Both buttons always open the Standard (`x`) config, even when the reference class is **XL**. Set the class to **Standard** before you apply a suggestion.
</Warning>

<Note>
  When every rate on a community's config for the reference class is zero, Yelo rides are free. The tab doesn't score parity in that case, but still plots competitor quotes.
</Note>

### Review provider responses

The **Provider responses** table lists every priced option the app received from a connected provider in the period. Columns include provider, product, class, miles, minutes, surge, fare, the **Ex-surge** fare, the matching Yelo fare, the ratio, the band, and the quote pass. **Minutes** and **Quote pass** are hidden until you turn them on under **Columns**. Filter by provider, class, or band, or search by product or quote pass. Expand a row to see the full quote pass the rider was shown.

Quotes come from Fare Finder on rider app versions that report per-offer fares, and only from riders who allow Fare Finder diagnostics. Yelo copies new quotes from analytics every 5 minutes, and the header shows when quotes were last **synced**. The first sync loads the last 90 days. Each period loads at most the newest 5,000 quotes. Test and internal devices are included, because a provider's quote is the same whoever asks for it. The tab refreshes every 5 minutes. Until the first sync finishes, the tab shows **No quote sync has run yet.** If that message doesn't clear, quote analytics isn't connected on the API. If the request fails, the tab shows **Competitor quotes could not be loaded.** with a **Retry** button.

For the endpoint behind this tab, see [Competitor quotes](/engineering/domains/dashboard-analytics#competitor-quotes).
