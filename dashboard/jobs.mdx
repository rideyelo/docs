The **Jobs** page embeds River UI, the dashboard for Yelo's background job queue. Use it to check whether scheduled work is running, find failed jobs, and retry or cancel them.

## Prerequisites

- An admin account. See [Dashboard roles and access](/administration/dashboard-roles).

## Open jobs

1. Expand **Administration** in the sidebar.
2. Click **Jobs**.

The page signs you in to River UI with your dashboard session and renews that session every 45 seconds while the page is open. If the session can't be created, the page shows an error and keeps retrying:

- **You appear to be offline. Jobs will reconnect automatically.**
- **Jobs could not establish an authenticated session. Retrying automatically.**

River UI is served by the Yelo API at `/riverui`. In production, the page always loads it from `https://api.rideyelo.com/riverui`, even though other dashboard requests default to `https://api.joinyelo.com`. The API rejects anyone who isn't an admin, even if they open that URL directly.

## What you can do in River UI

River UI lists jobs by state, queue, and kind. From it you can:

- See jobs that are running, scheduled, retrying, or discarded.
- Open a job to see its arguments, attempts, and errors.
- Retry, cancel, or delete a job.
- Check each queue's activity.

<Warning>
  Actions in River UI change production jobs immediately. Retrying a job can repeat side effects, such as sending a notification or a Stripe request.
</Warning>

## Recurring jobs

Yelo schedules these jobs on a fixed interval. Use the kind to find them in River UI. If a kind stops appearing, the work it does has stopped.

| Kind | Interval | What it does |
| --- | --- | --- |
| `contact_sync_dispatch` | 5 seconds | Dispatches pending contact sync work. See [Contact sync](/administration/contact-sync). |
| `contact_sync_scan` | 1 minute | Scans for contacts that need syncing. |
| `quo_sync_outbox` | 5 seconds | Sends queued changes to Quo. |
| `quo_sync_batch` | 1 minute | Runs Quo backfill and reconcile batches. |
| `calendar_sync_dispatch` | 15 seconds | Dispatches calendar syncs for operating hours. See [Operating hours](/admin/operating-hours). |
| `community_geography_maintenance` | 15 seconds | Maintains community geography, such as time zones. |
| `place_identity_backfill` | 1 minute | Backfills shared place records. |
| `stripe_reconciliation_dispatch` | 1 minute | Dispatches Stripe account reconciliation. |
| `top_locations_dispatch` | 5 minutes | Refreshes community top locations. See [Community top locations](/guides/community-top-locations). |
| `top_locations_verify_legacy` | 1 hour | Verifies older top location records. |
| `google_play_release_check` | 5 minutes | Checks Google Play for new app releases. |
| `gtm_refresh` | 5 minutes | Rebuilds the cached snapshot of users without a real community. No dashboard page or API route reads this snapshot. |
| `notify_receipt_check` | 5 minutes | Checks push notification delivery receipts. |
| `notify_recovery` | 5 minutes | Recovers notifications that didn't finish sending. |
| `stripe_drive_fee_scan` | 10 minutes | Scans recent rides for drive fee history that needs repair, and queues `stripe_drive_fee_repair` jobs. |

Other job kinds, such as `notify_send`, `contact_sync_user`, and `ride_operation`, run on demand when something in the app triggers them.

## Queues

| Queue | Used for |
| --- | --- |
| `default` | Jobs that don't name a queue. |
| `operating_hours` | Calendar syncs. |
| `top_locations` | Top location refreshes. |
| `quo` and `quo_control` | Quo contact sync. |
| `gtm` | The `gtm_refresh` job. |
| `stripe` and `stripe_reconciliation` | Stripe drive fees and account reconciliation. |

Contact sync adds its own queues on top of these.
