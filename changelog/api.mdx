This page tracks merged pull requests in `rideyelo/yelo-api`, newest week first. Weeks start on Monday and use the merge date in UTC.

Markers on each line:

- **Migration**: adds files under `migrations/`. The release pipeline applies them before the new revision takes traffic. See [Deployment](/engineering/deployment).
- **Breaking**: changes an HTTP contract, an authorization rule, or a behavior that a client or operator has to adapt to.
- **Config**: needs an environment variable, secret, trigger setting, or dashboard setting outside the code. See [Environment variables](/reference/environment-variables).

Dependency bumps, CI changes, and E2E tooling are summarized in one line per week.

<Update label="Week of September 21, 2026" description="Live market operations API, silent ride cancellation, fleet membership editing and archive guards, canonical top locations, and coordinate-only stops">
  **Dashboard**

  - **Breaking.** Market operations moved from `/dashboard/supply-demand/*` to `/dashboard/live/*`. The routes add scoped ride analytics, prior-period comparisons, timing ranges, cancellation flows, cached competitor quotes, effective operating hours, and recent driver locations. **Config:** competitor quotes need `POSTHOG_PERSONAL_API_KEY` and `POSTHOG_PROJECT_ID`. `POSTHOG_QUERY_HOST` defaults to `https://us.posthog.com`. The optional `DASHBOARD_PREVIEW=true` needs `ENVIRONMENT=dev`. [#277](https://github.com/rideyelo/yelo-api/pull/277). See [Live operations](/dashboard/live).
  - Admins can silently cancel a free, accepted ride (`driver_en_route`, `driver_waiting`, or `in_progress`). The cancellation skips notifications and payments and is guarded by the ride's lifecycle revision. New endpoints: `GET /dashboard/rides/{id}/silent-cancellation` and `POST /dashboard/rides/{id}/silent-cancel`. [#278](https://github.com/rideyelo/yelo-api/pull/278). See [Admin silent cancellation](/concepts/cancellations#admin-silent-cancellation).
  - Uncomplete metrics, totals, and ride lists only count confirmed rides that never matched, and exclude superseded searches. Pre-match cancellations split into `match_timeout`, `rider_cancel`, `driver_cancel`, and `unknown_cancel`. **Breaking** for consumers with fixed category mappings. [#254](https://github.com/rideyelo/yelo-api/pull/254). See [Ride metrics](/dashboard/ride-metrics).
  - Community and fleet KPIs add `confirmed_requests`. `completion_rate` is now completed confirmed rides divided by confirmed requests. [#255](https://github.com/rideyelo/yelo-api/pull/255). See [Ride metrics](/dashboard/ride-metrics).
  - Derived fleet tags require an activated driver application, and the activation check is scoped to the target user. **Migration** `000343` and `000344` replace `dashboard_user_tags`, with no table changes or backfill. [#261](https://github.com/rideyelo/yelo-api/pull/261), [#263](https://github.com/rideyelo/yelo-api/pull/263). See [User directory](/dashboard/user-directory).
  - Log triage fixes. Idle drivers show up in driver options again, after only busy drivers had been offered. Fleet Stripe status no longer returns 500 for accounts that haven't finished onboarding. Stripe accounts rejected outright count as `invalid` and are rechecked weekly. `num_seats` is validated against the vehicle type's `min_seats`. **Breaking:** dashboard role and scope denials in handlers return 403 instead of 401, and lead messages add a required `phone_invalid` field. [#266](https://github.com/rideyelo/yelo-api/pull/266). See [Direct requests](/engineering/matching/direct-requests) and [Vehicle types and catalog](/engineering/domains/vehicle-types-and-catalog).

  **Fleets**

  - Admins can read and edit a driver's fleet memberships and active fleet with `GET` and `PUT /dashboard/users/detail/{id}/fleets`. Edits are rejected during rides, take idle drivers offline, and update payout routing and shared vehicle selection in one transaction. Archiving a fleet is refused until its drivers, payouts, rides, sessions, primary communities, vehicles, and QR links are cleared. **Migration** `000346` adds archive reference-guard triggers. **Breaking:** legacy email enrollment is admin-only, and automatic enrollment only uses the default community's primary fleet. **Config:** that fleet must be active core Yelo with `owner_operator` payouts and `has_custom_payouts = false`. [#273](https://github.com/rideyelo/yelo-api/pull/273). See [Fleet Stripe accounts and lifecycle](/engineering/fleets/stripe-and-lifecycle) and [Active fleet, membership, and payout routing](/engineering/fleets/membership-and-payout-routing).

  **Rides and matching**

  - Immediate (T0) ride notifications no longer check seats. The check compared against `num_riders`, which is null until the trip is rated, so it matched no drivers. [#275](https://github.com/rideyelo/yelo-api/pull/275). See [Notification fan-out](/engineering/matching/notification-fan-out).
  - The `verified_student` badge now follows the fleet's `is_student_only` setting instead of the fleet name `Yelo`. [#276](https://github.com/rideyelo/yelo-api/pull/276). See [Rider option ordering and badges](/engineering/fleets/isolation#rider-option-ordering-and-badges).
  - Ride options carry at most one badge, picked in the order `verified_student`, `fleet`, `cheapest`, `fastest`. The community's primary fleet no longer gets a `fleet` badge. [#280](https://github.com/rideyelo/yelo-api/pull/280). See [Rider option ordering and badges](/engineering/fleets/isolation#rider-option-ordering-and-badges).
  - Missing or "Current location" stop addresses are resolved before any ride, location, or payment write. Stops are compared by coordinates, and transient geocoding failures are retried once. **Config:** needs Mapbox permanent-geocoding access. [#267](https://github.com/rideyelo/yelo-api/pull/267). See [Search, geocoding, and places](/engineering/location/search-and-places#reverse-geocoding).
  - Coordinate stops are accepted even when address lookup fails. Stops without an address skip address caches, search tracking, and address-targeted discounts. **Migration** `000347` restores the `Locations_address_key` unique constraint on fresh databases and is a no-op in production. [#274](https://github.com/rideyelo/yelo-api/pull/274). See [Search, geocoding, and places](/engineering/location/search-and-places#reverse-geocoding).
  - Idle drivers' auto-assignments start right away, and stranded queued rides are recovered by existing maintenance. Assignment is recorded before promotion. [#264](https://github.com/rideyelo/yelo-api/pull/264). See [Queue promotion and recovery](/engineering/matching/queue-promotion).
  - `ride_auto_queued` events record candidate count, deadhead minutes, final score, queue load, and confirm-to-assignment time again. [#268](https://github.com/rideyelo/yelo-api/pull/268). See [Auto-queue scoring](/engineering/matching/auto-queue-scoring).

  **Places**

  - Community top locations point to canonical Yelo place profiles, with per-community visibility and an opt-in 24-hour River refresh. **Migration** `000345` adds place profiles, community slots, and settings. It backfills existing entries as manual and unverified, and hides every community's list by default. **Breaking:** dashboard create and update take place references instead of venue snapshots. [#265](https://github.com/rideyelo/yelo-api/pull/265). See [Community top locations](/guides/community-top-locations).

  **Platform**

  - `/metrics` and `/debug/pprof` are only mounted when `METRICS_AUTH_TOKEN` is set. `PPROF_ENABLED` now defaults to `false`. **Config:** production reads the token from the `yelo-api-metrics-auth-token` secret. Local `.env` files need `METRICS_AUTH_TOKEN` for the local Prometheus stack. [#279](https://github.com/rideyelo/yelo-api/pull/279). See [Observability](/engineering/observability).
  - Dependencies: maps, Twilio, gRPC, and OpenTelemetry modules. [#262](https://github.com/rideyelo/yelo-api/pull/262)
</Update>

<Update label="Week of September 14, 2026" description="Ride state snapshots, fleet calendars, shared fleet vehicles, contact sync, place identity, dashboard authorization scopes, and whole-dollar fares">
  **Rides and matching**

  - Ride state is protected by authoritative snapshots, monotonic revisions, assignment generations, and transactional lifecycle fences. **Migration** `000336` to `000342` add revision counters, operation journal and cancellation-quote tables, E2E fixture constraints, and backfill `payment_consent_at` from `confirm_time`. **Config:** set `RIDE_STATE_SNAPSHOT_ENABLED=true` only after every writer runs the revision-aware binary. New clients negotiate `X-Ride-State-Protocol: 1`. **Breaking:** the minimum app version is 5.7.3, and older apps get HTTP 426. [#253](https://github.com/rideyelo/yelo-api/pull/253). See [Concurrency and races](/engineering/matching/concurrency).
  - Non-Yelo fleets get T0 alerts whether or not they're the community's primary fleet. [#237](https://github.com/rideyelo/yelo-api/pull/237). See [Notification fan-out](/engineering/matching/notification-fan-out).
  - "Current location" pickup labels are replaced with the pickup address before the ride is stored. [#243](https://github.com/rideyelo/yelo-api/pull/243). See [Search, geocoding, and places](/engineering/location/search-and-places).

  **Fleets and vehicles**

  - Fleets can own shared vehicles with per-vehicle approval, a default selection, and inherited application approval. Drivers can share a vehicle at the same time. **Migration** `000333` adds fleet ownership and selection triggers. `000334` seeds the Tallahassee Breeze cart. `000335` creates the mobile artwork catalog. **Breaking** deploy order: drain driver traffic during the cutover, because the old API can't read ownerless vehicles. [#242](https://github.com/rideyelo/yelo-api/pull/242). See [Fleet vehicles and vehicle resolution](/engineering/fleets/vehicles) and [Fleet vehicles](/dashboard/fleet-vehicles).
  - Vehicle catalog republication reuses byte-identical artwork instead of returning 502. [#248](https://github.com/rideyelo/yelo-api/pull/248). See [Vehicle types and catalog](/engineering/domains/vehicle-types-and-catalog).
  - Owner-operator fleets can create and redeem invitations without fleet Stripe onboarding. [#251](https://github.com/rideyelo/yelo-api/pull/251). See [Fleet joins and invitation links](/engineering/fleets/joins-and-invitations).
  - Fleet calendars are imported from Google Calendar every five minutes, and community timezones are derived from bounds. **Migration** `000314` to `000318` retire waitlisting, add timezone history, backfill fleet service communities, and add calendar credentials, bindings, and snapshots. **Breaking:** bounds updates require `expected_geography_revision`, and retired capacity fields return validation errors. **Config:** calendar OAuth credentials, URLs, owner email, and token encryption keys go on the `yelo-api-release-manual` trigger. [#197](https://github.com/rideyelo/yelo-api/pull/197). See [Fleet service communities and operating calendars](/engineering/fleets/service-communities-and-calendars).
  - Admins can rename calendar zone prefixes. Zone geometry and descriptions are returned for the dashboard calendar. **Migration** `000319`. [#220](https://github.com/rideyelo/yelo-api/pull/220). See [Fleet operating hours](/admin/operating-hours).
  - Admins can correct fleet calendar IDs. Community and rider hours come from the primary fleet calendar. User and lead fleet tags are derived from active membership. **Migration** `000320` and `000321`. [#224](https://github.com/rideyelo/yelo-api/pull/224). See [Fleet operating hours](/admin/operating-hours).

  **Dashboard**

  - Dashboard roles and assignments are enforced for interns and fleet managers, including on global endpoints. **Breaking:** missing or malformed Clerk assignments are denied. [#228](https://github.com/rideyelo/yelo-api/pull/228). See [Dashboard roles and access](/administration/dashboard-roles).
  - Ride maps with optional route geometry, ride ID search, typo-tolerant user search, and tag filters. **Breaking:** the retired dashboard GTM endpoints are removed. [#213](https://github.com/rideyelo/yelo-api/pull/213). See [User directory](/dashboard/user-directory).
  - Admins can manually activate approved driver leads. [#221](https://github.com/rideyelo/yelo-api/pull/221). See [Driver leads pipeline](/dashboard/driver-leads).
  - App version telemetry returns every version and filters by report age (`app_version_months`). [#226](https://github.com/rideyelo/yelo-api/pull/226). See [Telemetry](/dashboard/telemetry).

  **Pricing**

  - Pricing configs can add jitter, round up to whole dollars, or leave fares unadjusted. Admins manage global jitter settings. **Migration** `000324` and `000325`. [#232](https://github.com/rideyelo/yelo-api/pull/232). See [Global jitter settings](/dashboard/ride-pricing#global-jitter-settings).

  **Contact sync**

  - Contact profiles sync to Resend and Quo through a shared engine with change-driven jobs and periodic reconciliation. **Migration** `000322` and `000323`. **Config:** a dedicated contacts secret, Resend enablement, account alias, and 200 ms Quo pacing on the release trigger. [#227](https://github.com/rideyelo/yelo-api/pull/227). See [Contact sync](/administration/contact-sync).
  - `GET /dashboard/contact-sync` reports sync progress. Resend reads no longer send a request body. [#229](https://github.com/rideyelo/yelo-api/pull/229)
  - Resend contact throughput rises to 5 requests per second under a shared 8 per second budget. **Config:** `RESEND_REQUEST_INTERVAL=125ms` and `RESEND_CONTACT_REQUEST_INTERVAL=200ms` on the release trigger. [#230](https://github.com/rideyelo/yelo-api/pull/230). See [Contact sync internals](/engineering/domains/contact-sync).
  - Admins can build marketing segments from typed filters, reconciled through River. **Migration** `000332` adds segment tables, activity triggers, and a contact refresh backfill. [#239](https://github.com/rideyelo/yelo-api/pull/239). See [Contact sync](/administration/contact-sync).
  - Reliability: Quo binding imports are batched ([#231](https://github.com/rideyelo/yelo-api/pull/231)), control jobs are coalesced ([#233](https://github.com/rideyelo/yelo-api/pull/233)), and the signup subscription choice survives rejected creates ([#234](https://github.com/rideyelo/yelo-api/pull/234)).

  **Places**

  - Stored places get an application-owned identity across locations, likes, recents, venues, bumps, and ride stops. **Migration** `000326` to `000328` add the place catalog, provider aliases, and a resumable River backfill. [#238](https://github.com/rideyelo/yelo-api/pull/238). See [Search, geocoding, and places](/engineering/location/search-and-places).
  - **Migration** `000331` skips oversized provider aliases so the identity backfill can finish. [#241](https://github.com/rideyelo/yelo-api/pull/241)
  - POI enrichment fixes for YELO-1279: bounded name extensions ([#244](https://github.com/rideyelo/yelo-api/pull/244)), abbreviated street names and `yelo_place_id` on recents sync ([#246](https://github.com/rideyelo/yelo-api/pull/246)), no 15-minute repair cooldown and Google profiles preferred ([#247](https://github.com/rideyelo/yelo-api/pull/247)), local label variants and paginated text search ([#249](https://github.com/rideyelo/yelo-api/pull/249)), ranking by distance and name evidence ([#250](https://github.com/rideyelo/yelo-api/pull/250)), and street-address recovery queries ([#252](https://github.com/rideyelo/yelo-api/pull/252)). **Config:** #252 needs Geocoding API access on the Google Maps key. See [Search, geocoding, and places](/engineering/location/search-and-places).

  **Notifications**

  - Signup Slack alerts are sent once, 90 seconds after signup, with fewer fields. [#222](https://github.com/rideyelo/yelo-api/pull/222). See [Slack alerts](/engineering/notifications/slack-alerts).
  - Template saves reject malformed placeholders and unsupported settings. Dispatch lists show sender names. **Breaking** for saves that used to be accepted. [#223](https://github.com/rideyelo/yelo-api/pull/223). See [Templates and rendering](/engineering/notifications/templates-and-rendering).
  - Dashboard (Clerk) actors are stored separately from app users on schedules, dispatches, and template edits. **Migration** `000329` and `000330`. [#240](https://github.com/rideyelo/yelo-api/pull/240). See [Operator broadcasts and scheduling](/engineering/notifications/broadcasts-and-scheduling).

  **Accounts and communities**

  - The reserved Yelo community is excluded from automatic assignment, and ordinary accounts in it are repaired on their next community resolution. [#212](https://github.com/rideyelo/yelo-api/pull/212), [#214](https://github.com/rideyelo/yelo-api/pull/214). See [Community assignment by location](/engineering/location/community-assignment).
  - Test accounts (`is_test`) keep their community during Auth v3 geo resolution. [#235](https://github.com/rideyelo/yelo-api/pull/235)
  - Hosted Auth v3 redirects keep the app channel and transaction ID. [#236](https://github.com/rideyelo/yelo-api/pull/236). See [Auth v3 transaction lifecycle](/engineering/identity/auth-v3-transactions).
  - School verification keeps an authenticated session instead of replacing it with a presignup token. [#245](https://github.com/rideyelo/yelo-api/pull/245). See [School verification](/engineering/identity/school-verification).

  **Platform**

  - Dependencies: pgx, oauth2, uuid, and Redis test modules. [#225](https://github.com/rideyelo/yelo-api/pull/225)
</Update>
