This page tracks merged pull requests in `rideyelo/yelo-api`, newest week first. Weeks start on Monday and use the merge date in UTC.

Markers on each line:

- **Migration**: adds files under `migrations/`. The release pipeline applies them before the new revision takes traffic. See [Deployment](/engineering/deployment).
- **Breaking**: changes an HTTP contract, an authorization rule, or a behavior that a client or operator has to adapt to.
- **Config**: needs an environment variable, secret, trigger setting, or dashboard setting outside the code. See [Environment variables](/reference/environment-variables).

Dependency bumps, CI changes, and E2E tooling are summarized in one line per week.

<Update label="Week of October 5, 2026" description="Driver net and pending earnings, anonymous link touches, ambient referral credit, self-healing Dub share links, friend_joined push, idempotent ride accept, ride financial command runtime, legacy update gate, Fare Finder kill switch, competitor quotes and parity window, minimum app version 5.7.4, invite friendships, ride v2 benchmark replay, and dependency updates">
  **Retired routes**

  - 46 unused operations are removed, including ads (`/ad/*`), coupons (`/coupon/*`), the promo bar (`GET /promobar/`), event attendance (`/event/{id}/attend`, `/event/{id}/attendees`), and the manual KPI log. Event responses drop `attendees` and `is_attending`, `GET /dashboard/kpi/global` drops `total_attenders` and the `attenders` series, and the community feed no longer has `ad` items. Callers get 404 or 405. **Breaking**. [#322](https://github.com/rideyelo/yelo-api/pull/322). See [Deprecated and legacy code](/engineering/history/deprecated-and-legacy#retired-in-october-2026).

  **Notifications**

  - New `friend_joined` push ("[Name] is on Yelo 👋", opens `/map`). It goes to the other side of each newly created friendship from a contact match, signup referral, or invite link, and is deduplicated per joiner and recipient set. It is a `marketing` template, so it defers to quiet hours. [#299](https://github.com/rideyelo/yelo-api/pull/299). See [Notification catalog](/engineering/notifications/catalog#operator-and-friends).

  **Rides**

  - Manual accepts are serialized per ride under the ride's advisory lock, so a duplicate request can't place a second authorization on the rider's card. A repeat accept from the driver who already holds the ride returns success instead of an error. A lifecycle conflict while saving the payment intent returns the conflict instead of a 500. [#295](https://github.com/rideyelo/yelo-api/pull/295). See [Concurrency and races](/engineering/matching/concurrency#race-scenarios).
  - `POST /ride/v2/` records per-stage timings for service stages, Postgres pool acquisition and named queries, Redis commands, and Mapbox and Stripe HTTP calls. Every completed request logs one `ride performance completed` record with `request_id`, `trace_id`, `status_code`, and `ride_performance`, regardless of OpenTelemetry sampling. `ride_performance` holds operation names, start offsets, durations, outcomes, call counts, and bounded workload flags and counts, never request bodies, coordinates, or user and ride IDs. A new **Benchmark isolated E2E API** workflow (`make cloud-api-benchmark`) replays an eight-case `/ride/v2/` suite against the E2E service and compares two revisions. It touches no production state and needs no migration. Benchmark fixture writes are batched, and runs keep their captures as workflow artifacts. [#314](https://github.com/rideyelo/yelo-api/pull/314), [#317](https://github.com/rideyelo/yelo-api/pull/317)

  **Social**

  - `POST /user/friends/contacts` accepts up to 10,000 `phone_numbers`, up from 5,000. The mobile app raised its snapshot cap to match in [yelo-frontend#657](https://github.com/rideyelo/yelo-frontend/pull/657). [#295](https://github.com/rideyelo/yelo-api/pull/295). See [User social graph](/engineering/domains/user-social-graph#request-validation).

  **Communities**

  - New community kill switch `fare_finder_disabled`, default `false`. Admins set it through the admin community update, and the community model returns it. When it is `true`, the mobile app hides Fare Finder for riders in that community. **Migration** `000353` adds `Communities.fare_finder_disabled`. [#312](https://github.com/rideyelo/yelo-api/pull/312). See [Controls](/dashboard/communities#controls).
  - New `GET /dashboard/live/competitor-quotes` returns one row per priced Fare Finder tier for a market and period: provider, product, trip miles and minutes, surge, fare, whether the fare is at the provider minimum, and Lyft's rate card. It reads `ride_provider_request_completed` offers from PostHog, includes internal devices, excludes test devices, keeps the newest 5,000 offers, and caches for 5 minutes. `competitor-prices` and `competitor-quotes` accept any `<n>h` or `<n>d` period, or `all`. Communities gain a parity window, `parity_ratio_min` and `parity_ratio_max` (Yelo fare divided by the reference competitor fare). Admins set both together, each between 0.5 and 1.5, with the minimum below the maximum. **Migration** `000354` adds both columns with defaults `0.80` and `0.95`. [#318](https://github.com/rideyelo/yelo-api/pull/318). See [Competitor quotes](/engineering/domains/live-operations#competitor-quotes).

  **Payments**

  - Driver-facing earnings are net of Stripe's processing fee. Ride board, queue, ride details for drivers, message threads, drive history, and activity rows return `driver_earnings` (dollars) or `earnings` (cents). Status poll earnings and the weekly headline sum net earnings instead of `driver_payout`. Fees use the actual Stripe fee per charge when known, else a stored 2.9% + 30¢ estimate. Driver-facing reads show the rider's first name and last initial only. The fee repair job also stores dedicated tip charge fees and logs `stripe_fee_estimate_mismatch` when Stripe's fee differs from the estimate. **Migration** `000348` adds three fee columns to `Rides` and the `stripe_fee_estimate_cents` and `ride_driver_earnings_cents` functions. `000349` and `000350` add concurrent tip-fee repair indexes. **Breaking:** drive history `fee_cents` is now gross less `driver_earnings`, and rider history no longer returns a fee. [#298](https://github.com/rideyelo/yelo-api/pull/298). See [Driver earnings and activity](/engineering/domains/driver-earnings-and-activity#net-earnings-after-stripe-fees).
  - `GET /earnings/balance` adds `uncaptured` and `uncaptured_rides` for completed rides whose fare is authorized but not captured. The first activity page lists them as `pending: true` rows, and drive history flags them with `pending`. Rating a ride pings the driver so the app refreshes. Fee estimates now use the authorized amount (fare + $5.00 when tips are on). **Migration** `000352` adds `ride_fare_fee_estimate_cents` and a 9-argument `ride_driver_earnings_cents`, and re-estimates stored fees with no actual fee yet. [#301](https://github.com/rideyelo/yelo-api/pull/301). See [Pending rides](/engineering/domains/driver-earnings-and-activity#pending-uncaptured-rides).
  - Ride money now moves only through the ride financial command runtime. Driver accept, auto-queue assignment, idle queue promotion, completion, cancellation, rating tips, tip confirmation, the tip-window sweeper, and unmatched-request expiry each reserve a `RideOperations` row before any Stripe call and execute from it. The direct Stripe writers in the ride service are removed. Every accept now assigns the ride first and authorizes afterwards, a ride accepted into a driver's queue is authorized when it's promoted, a declined card cancels the ride with `cancel_reason = 'Payment Failed'`, a driver-cancel requeue voids its hold before the ride rejoins matching, and expiry voids any hold that is still attached. Ride timeline events for these commands commit with the financial outcome and carry `operation_id`. `merchant_selected`, `payment_intent_created`, `payment_confirmed`, `payment_canceled`, and `payment_processing_failed` are no longer written. **Breaking:** a rider canceling a ride that has a payment hold needs a current quote from `POST /ride/i/{id}/cancel-intent` (valid 60 seconds, for the ride's current revision), or the cancel returns "Review cancellation fee". The mobile app already requests one. Accept rejections that used to return "Driver Not Online", "Driver Queue Length Exceeded", "Ride request no longer valid", "Ride is awaiting the selected driver", or a fleet mismatch now return the generic conflict "Ride Unavailable", and an accept from a driver with no open session returns a 500 instead of "No Active Session". While a command is unresolved, every other command on that ride returns the same conflict. The pull request also calls for draining instances that run the old writers before this revision takes ride traffic. [#316](https://github.com/rideyelo/yelo-api/pull/316). See [Ride operation journal](/engineering/payments/ride-operation-journal) and [Ride PaymentIntent lifecycle](/engineering/payments/ride-payment-intents).
  - The ride command runtime is assembled at startup with the production Stripe client, the ride service's pickup routing, and the notification River client, and its `ride_operation` and `ride_operation_recovery` workers run on a new `ride_operations` queue. A finished command keeps its job until the ride board and the driver's queue summary match the ride, then records a receipt. The recovery job re-enqueues finished commands that have no receipt and no live job. E2E instances start River with only the `ride_operations` queue, and fixture cleanup refuses to delete a run whose ride operations are unresolved or unacknowledged. `E2E_DATABASE_PROJECT_REF=local` is accepted for a loopback database named `yelo_e2e_*`. `make cover-integration-profile` takes `INTEGRATION_TEST_TIMEOUT` (default `10m`). **Migration** `000355` creates `RideOperationEffectReceipts`. It has no backfill. [#315](https://github.com/rideyelo/yelo-api/pull/315), [#316](https://github.com/rideyelo/yelo-api/pull/316). See [Terminal effects](/engineering/payments/ride-operation-journal#terminal-effects) and [E2E testing](/engineering/qa/e2e).

  **Referrals and attribution**

  - New public `POST /authv3/attribution/touch` records an anonymous link landing before any auth transaction exists. It takes the same attribution object as accept, with `anonymous_id` and `landing_surface` required, and stores the touch with no `auth_transaction_id`. The new `attribution_touch` rate scope allows 120 requests per 10 minutes per requester prefix. When a transaction resolves, it claims unclaimed touches with the same `anonymous_id` from the 90 days before authentication. At profile completion, if the user presented no code, the most recent referral code on those touches is applied, and invalid, self, or conflicting codes are dropped silently. Auth v3 signups with a claimed Dub click ID send a Dub `Sign Up` lead. **Config:** `REFERRAL_LANDING_BASE_URL` sets the destination base for personal invite links on `join.yelo.link`, intended as `https://joinyelo.com/i`. It falls back to `INVITE_LANDING_BASE_URL`, then `https://invite.yelo.link`. [#294](https://github.com/rideyelo/yelo-api/pull/294). See [Anonymous link touches](/engineering/domains/referrals-and-links#anonymous-link-touches) and [Record an anonymous link touch](/engineering/identity/auth-v3-transactions#record-an-anonymous-link-touch).
  - Changing the destination of an existing Dub link no longer fails with a duplicate-key conflict. Dub upserts match by destination URL, so on conflict the client now looks the link up by domain and key and updates it in place. [#297](https://github.com/rideyelo/yelo-api/pull/297). See [Share links](/engineering/domains/referrals-and-links#share-links).
  - Personal invite links heal themselves. `GET /referral/link` syncs the link and is a no-op when the stored fingerprint matches. If Dub fails and a link already exists, it serves the existing link instead of returning 500. A new `share_link_sweep` River job rewrites up to 40 stale links every minute, and name or photo changes mark the link stale. **Migration** `000351` adds `Users.share_link_created_at` and `Users.share_link_fingerprint`, and backfills existing links as unsynced so each is rewritten once. `has_dub_link` is no longer read by the API. [#300](https://github.com/rideyelo/yelo-api/pull/300). See [Self-healing sweep](/engineering/domains/referrals-and-links#self-healing-sweep).
  - Auth v3 signup with an invite code now makes the inviter and invitee friends in the same transaction that records the referral. Before, it recorded the referral only. There is no backfill, so earlier Auth v3 invite signups keep a referral with no friendship. Personal and fleet invite links now land on `INVITE_LANDING_BASE_URL`, which defaults to `https://joinyelo.com/i`. Invite share cards carry a design version, and the share link version moves to `4`, so the sweep rewrites every link once with the new card. **Config:** `REFERRAL_LANDING_BASE_URL` is removed. Set `INVITE_LANDING_BASE_URL` only to override the default. [#309](https://github.com/rideyelo/yelo-api/pull/309). See [Self-healing sweep](/engineering/domains/referrals-and-links#self-healing-sweep).

  **Platform**

  - New standalone App Engine service for the retired host `prod-yelo.uc.r.appspot.com`. App builds 4.x and older get `426 Upgrade Required` with the store link. `/update-required` is proxied to the live API. **Config:** deployed manually with `gcloud app deploy`, outside the release pipeline. [#295](https://github.com/rideyelo/yelo-api/pull/295). See [Legacy update gate](/engineering/deployment#legacy-update-gate).
  - `/update-required` now requires app version 5.7.4, up from 5.7.3. Older builds get `426 Upgrade Required` with the store link. **Breaking:** riders and drivers on 5.7.3 or older are blocked until they update from the store, including during an active trip. [#313](https://github.com/rideyelo/yelo-api/pull/313). See [Health and update gate](/engineering/domains/app-stores-and-telemetry#health-and-update-gate).
  - API deploy and release failure Slack alerts are two lines: `*API deployed* · <author> · <title>`, then links to the Cloud Run revisions, the workflow run, and the pull request, with build and deploy durations. A failure alert names the first failed stage. [#311](https://github.com/rideyelo/yelo-api/pull/311)
  - Dependencies: maps, Dub, OTLP trace exporter, `x/net`, and Google API modules ([#291](https://github.com/rideyelo/yelo-api/pull/291)), then River 0.48, Twilio, OpenTelemetry, and Google API modules ([#310](https://github.com/rideyelo/yelo-api/pull/310)).
</Update>

<Update label="Week of September 21, 2026" description="Live market operations API, silent ride cancellation, fleet membership editing and archive guards, canonical top locations, coordinate-only stops, and the ride financial command journal foundation">
  **Dashboard**

  - **Breaking.** Market operations moved from `/dashboard/supply-demand/*` to `/dashboard/live/*`. The routes add scoped ride analytics, prior-period comparisons, timing ranges, cancellation flows, cached competitor quotes, effective operating hours, and recent driver locations. **Config:** competitor quotes need `POSTHOG_PERSONAL_API_KEY` and `POSTHOG_PROJECT_ID`. `POSTHOG_QUERY_HOST` defaults to `https://us.posthog.com`. The optional `DASHBOARD_PREVIEW=true` needs `ENVIRONMENT=dev`. [#277](https://github.com/rideyelo/yelo-api/pull/277). See [Live operations](/dashboard/live).
  - Admins can silently cancel a free, accepted ride (`driver_en_route`, `driver_waiting`, or `in_progress`). The cancellation skips notifications and payments and is guarded by the ride's lifecycle revision. New endpoints: `GET /dashboard/rides/{id}/silent-cancellation` and `POST /dashboard/rides/{id}/silent-cancel`. [#278](https://github.com/rideyelo/yelo-api/pull/278). See [Admin silent cancellation](/concepts/cancellations#admin-silent-cancellation).
  - Uncomplete metrics, totals, and ride lists only count confirmed rides that never matched, and exclude superseded searches. Pre-match cancellations split into `match_timeout`, `rider_cancel`, `driver_cancel`, and `unknown_cancel`. **Breaking** for consumers with fixed category mappings. [#254](https://github.com/rideyelo/yelo-api/pull/254). See [Ride metrics](/dashboard/ride-metrics).
  - Community and fleet KPIs add `confirmed_requests`. `completion_rate` is now completed confirmed rides divided by confirmed requests. [#255](https://github.com/rideyelo/yelo-api/pull/255). See [Ride metrics](/dashboard/ride-metrics).
  - Derived fleet tags require an activated driver application, and the activation check is scoped to the target user. **Migration** `000343` and `000344` replace `dashboard_user_tags`, with no table changes or backfill. [#261](https://github.com/rideyelo/yelo-api/pull/261), [#263](https://github.com/rideyelo/yelo-api/pull/263). See [User directory](/dashboard/user-directory).
  - Log triage fixes. Idle drivers show up in driver options again, after only busy drivers had been offered. Fleet Stripe status no longer returns 500 for accounts that haven't finished onboarding. Stripe accounts rejected outright count as `invalid` and are rechecked weekly. `num_seats` is validated against the vehicle type's `min_seats`. **Breaking:** dashboard role and scope denials in handlers return 403 instead of 401, and lead messages add a required `phone_invalid` field. [#266](https://github.com/rideyelo/yelo-api/pull/266). See [Direct requests](/engineering/matching/direct-requests) and [Vehicle types and catalog](/engineering/domains/vehicle-types-and-catalog).
  - New `GET /dashboard/driver-ops/drivers/{id}` returns one driver's live operations context for the driver sheet on **Live**. Drivers who aren't idle online also get their active ride, queue, earnings, and payout. Market drivers add `session_start_time` and `location_updated_at`, and admin map user coordinates add `location_updated_at`. User detail adds `awaiting_rating_earnings`, the expected payout for uncanceled drives awaiting a rider rating. It isn't a Stripe balance. Ride history items add `is_canceled` and `cancel_user`. A driver's drive history now includes rides they canceled or that were auto-requeued away from them. Accounts without a profile photo fall back to their driver application photo. [#283](https://github.com/rideyelo/yelo-api/pull/283). See [Live operations](/dashboard/live#monitor-drivers).
  - `photo_url` in ride details, the ride board, dashboard lists, friends, event attendees, and invite previews returns the 512px thumbnail when one exists and the full photo otherwise. Driver avatars prefer the driver photo's thumbnail over the account photo. Friends and invite previews no longer go blank when no thumbnail exists. No contract change. [#281](https://github.com/rideyelo/yelo-api/pull/281). See [Profile photos](/engineering/domains/user-profile-and-status#profile-photos).

  **Fleets**

  - Admins can read and edit a driver's fleet memberships and active fleet with `GET` and `PUT /dashboard/users/detail/{id}/fleets`. Edits are rejected during rides, take idle drivers offline, and update payout routing and shared vehicle selection in one transaction. Archiving a fleet is refused until its drivers, payouts, rides, sessions, primary communities, vehicles, and QR links are cleared. **Migration** `000346` adds archive reference-guard triggers. **Breaking:** legacy email enrollment is admin-only, and automatic enrollment only uses the default community's primary fleet. **Config:** that fleet must be active core Yelo with `owner_operator` payouts and `has_custom_payouts = false`. [#273](https://github.com/rideyelo/yelo-api/pull/273). See [Fleet Stripe accounts and lifecycle](/engineering/fleets/stripe-and-lifecycle) and [Active fleet, membership, and payout routing](/engineering/fleets/membership-and-payout-routing).

  **Rides and matching**

  - Immediate (T0) ride notifications no longer check seats. The check compared against `num_riders`, which is null until the trip is rated, so it matched no drivers. [#275](https://github.com/rideyelo/yelo-api/pull/275). See [Notification fan-out](/engineering/matching/notification-fan-out).
  - The `verified_student` badge now follows the fleet's `is_student_only` setting instead of the fleet name `Yelo`. [#276](https://github.com/rideyelo/yelo-api/pull/276). See [Rider option ordering and badges](/engineering/fleets/isolation#rider-option-ordering-and-badges).
  - Ride options carry at most one badge, picked in the order `verified_student`, `fleet`, `cheapest`, `fastest`. The community's primary fleet no longer gets a `fleet` badge. [#280](https://github.com/rideyelo/yelo-api/pull/280). See [Rider option ordering and badges](/engineering/fleets/isolation#rider-option-ordering-and-badges).
  - Missing or "Current location" stop addresses are resolved before any ride, location, or payment write. Stops are compared by coordinates, and transient geocoding failures are retried once. **Config:** needs Mapbox permanent-geocoding access. [#267](https://github.com/rideyelo/yelo-api/pull/267). See [Search, geocoding, and places](/engineering/location/search-and-places#reverse-geocoding).
  - Coordinate stops are accepted even when address lookup fails. Stops without an address skip address caches, search tracking, and address-targeted discounts. **Migration** `000347` restores the `Locations_address_key` unique constraint on fresh databases and is a no-op in production. [#274](https://github.com/rideyelo/yelo-api/pull/274). See [Search, geocoding, and places](/engineering/location/search-and-places#reverse-geocoding).
  - Idle drivers' auto-assignments start right away, and stranded queued rides are recovered by existing maintenance. Assignment is recorded before promotion. [#264](https://github.com/rideyelo/yelo-api/pull/264). See [Queue promotion and recovery](/engineering/matching/queue-promotion).
  - `ride_auto_queued` events record candidate count, deadhead minutes, final score, queue load, and confirm-to-assignment time again. [#268](https://github.com/rideyelo/yelo-api/pull/268). See [Auto-queue scoring](/engineering/matching/auto-queue-scoring).
  - Public ride details return the assigned vehicle's `vehicle.type`, so clients can show the right artwork after a match. Riders matched with a cart no longer see car artwork. [#284](https://github.com/rideyelo/yelo-api/pull/284). See [Vehicle types and catalog](/engineering/domains/vehicle-types-and-catalog).

  **Payments**

  - Foundation for a durable ride financial command journal. Ride authorization is journaled before a hold is placed. Acceptance, promotion, cancellation, completion, and tip commands are reserved under the ride's lifecycle ownership, and they can resume from durable receipts after a crash or provider error. A new `ride_payment_failed` notification template tells riders when payment authorization can't complete. Authoritative ride-state snapshots add `pending_financial_rides`, and snapshot rides add `transition_pending`. Both are additive and omitted when empty, so older clients are unaffected. Financial runtime activation is still deferred, so live rides keep the existing payment path. [#269](https://github.com/rideyelo/yelo-api/pull/269), [#270](https://github.com/rideyelo/yelo-api/pull/270), [#271](https://github.com/rideyelo/yelo-api/pull/271), [#272](https://github.com/rideyelo/yelo-api/pull/272). See [Ride-state snapshot](/engineering/domains/user-profile-and-status#ride-state-snapshot) and [Ride payment intents](/engineering/payments/ride-payment-intents).

  **Places**

  - Community top locations point to canonical Yelo place profiles, with per-community visibility and an opt-in 24-hour River refresh. **Migration** `000345` adds place profiles, community slots, and settings. It backfills existing entries as manual and unverified, and hides every community's list by default. **Breaking:** dashboard create and update take place references instead of venue snapshots. [#265](https://github.com/rideyelo/yelo-api/pull/265). See [Community top locations](/guides/community-top-locations).

  **Platform**

  - `/metrics` and `/debug/pprof` are only mounted when `METRICS_AUTH_TOKEN` is set. `PPROF_ENABLED` now defaults to `false`. **Config:** production reads the token from the `yelo-api-metrics-auth-token` secret. Local `.env` files need `METRICS_AUTH_TOKEN` for the local Prometheus stack. [#279](https://github.com/rideyelo/yelo-api/pull/279). See [Observability](/engineering/observability).
  - Dependencies: maps, Twilio, gRPC, and OpenTelemetry modules. [#262](https://github.com/rideyelo/yelo-api/pull/262)
  - `make mocks` and `make mocks-check` run mockery under the Go toolchain from `go.mod`, so they match CI on any local Go version. [#282](https://github.com/rideyelo/yelo-api/pull/282)

  - Admins can correct fleet calendar IDs. Community and rider hours come from the primary fleet calendar. User and lead fleet tags are derived from active membership. **Migration** `000320` and `000321`. [#224](https://github.com/rideyelo/yelo-api/pull/224). See [Fleet operating hours](/admin/operating-hours).
