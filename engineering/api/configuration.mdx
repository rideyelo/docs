All runtime configuration comes from environment variables. This page lists variable names and their purpose. It never lists values for secrets. For where production values are stored and bound to Cloud Run, see [Deployment](/engineering/deployment). For a working local `.env`, start from `.env.example` and see [Local development](/engineering/local-development).

## How configuration loads

`config.Load()` in `internal/utilities/config/config.go` builds a `*config.Config` once, behind a `sync.Once`, and returns the same pointer on every call.

- It loads `.env` from the working directory if the file exists. A missing file is not an error.
- Unset variables take the default shown in code. Unparseable booleans, integers, floats, and durations silently fall back to the default. Auth v3 durations are the exception: they record a parse error that fails validation.
- List variables (`CORS_TRUSTED_ORIGINS`, `KEY_LEGACY`, `GOOGLE_PLAY_TRACKS`, and similar) accept commas or spaces.

<Warning>
Because `Load()` memoizes, changing an environment variable after startup has no effect. Tests that need a different value set it on the returned struct, for example `config.Load().Auth.AuthJwtKey = "..."`, or set the environment in `TestMain` before the first call.
</Warning>

A few values bypass the struct and read the environment directly: `PORT` (in `main.go`), `LOG_LEVEL` and `GOOGLE_CLOUD_PROJECT` (logger), `K_REVISION` (Postgres `application_name`), `BACKGROUND_TASKS_ENABLED` (background loops), and `CONTACT_HASH_PEPPER` (contact hashing, read on each use).

## Startup validation

`main.go` calls `cfg.Validate()` and panics on failure.

<Tabs>
  <Tab title="Normal mode">
    These variables are required:

    - `DSN`
    - `KEY`
    - `GOOGLE_ALLOWED_AUDIENCES`
    - `STRIPE_API_KEY`
    - `MAPBOX_API_KEY`
    - `GOOGLE_MAPS_API_KEY`
    - `TWILIO_ACCOUNT_SID`, `TWILIO_AUTH_TOKEN`, `TWILIO_PHONE_NUMBER`
    - `OG_SIGNING_SECRET`
    - `GOOGLE_PLAY_PACKAGE_NAME` and `GOOGLE_PLAY_TRACKS` when Google Play release monitoring is enabled

    When `AUTH_V3_ENABLED` is true, the required Auth v3 origins, legal versions, Google and Apple provider settings, and keys must also be present and parse correctly.
  </Tab>
  <Tab title="E2E mode">
    When `E2E_ENABLED=true` or `ENVIRONMENT=e2e`, `validateE2E` runs instead. It requires:

    - Both `E2E_ENABLED=true` and `ENVIRONMENT=e2e`.
    - `DSN`, `KEY`, `E2E_CONTROL_API_KEY` (at least 32 bytes), `E2E_DATABASE_NAME`, `E2E_DATABASE_PROJECT_REF`, and `E2E_PRODUCTION_DATABASE_PROJECT_REF`.
    - The `DSN` database name to match `E2E_DATABASE_NAME`, and its Supabase project ref to match `E2E_DATABASE_PROJECT_REF` and differ from the production ref.
    - Redis enabled on a nonzero logical database.
    - `E2E_BACKGROUND_JOBS_ENABLED` false and `E2E_FIXTURE_TTL` between 0 and 24 hours.
    - Stripe test keys (`sk_test_`, `pk_test_`).
    - Messaging, Quo, Dub, Slack, Photon, Resend, and Auth v3 provider secrets unset, so E2E can never contact real people.
  </Tab>
</Tabs>

Calendar settings are validated separately when the calendar services are built.

## Command-line flags

`cmd/api` also accepts flags. They override environment defaults.

| Flag | Default | Purpose |
| --- | --- | --- |
| `--port` | `PORT` or `8080` | Listen port |
| `--limiter-rps` | `50` | Per-IP requests per second |
| `--limiter-burst` | `100` | Per-IP burst |
| `--limiter-enabled` | `true` | Enables the rate limiter |
| `--cors-trusted-origins` | `CORS_TRUSTED_ORIGINS` | Overrides the CORS allowlist |
| `--stripe-key` | `STRIPE_API_KEY` | Overrides the Stripe key |

## Constants

`internal/utilities/config/constants.go` holds behavior constants that are not configurable at runtime:

| Constant | Value | Meaning |
| --- | --- | --- |
| `RideRequestExpiry` | 10 minutes | Unmatched confirmed rides are expired after this |
| `RideAcceptTimeout` | 25 seconds | Time a driver has to accept a request |
| `NoDriversAvailableDelay` | 45 seconds | Delay before telling the rider no drivers are available |
| `RecentlyOnlineDriverNotificationWindow` | 30 minutes | Window for "recently online" driver notifications |
| `DriverExpiryInterval` | 30 minutes | Inactivity before a driver is set offline |
| `DriverReminderInterval` | 30 seconds | Minimum gap between renew-online reminders per community |
| `OfflineGraceInterval` | 5 minutes | Grace before unqueuing rides for an offline driver |
| `CommunityWaitBuffer` | 5 minutes | Added to community wait estimates |
| `OtpExpiry` | 15 minutes | Auth v2 OTP lifetime |
| `WaitTimeCancellationCutoff` | 420 seconds | Driver wait before a cancellation fee applies |
| `TimeAwayCancellationCutoff` | 300 seconds | Driver distance-from-pickup threshold for rider cancellation fees |
| `DefaultBasePrice`, `DefaultPricePerMile`, `DefaultPricePerMinute` | 4.0, 2.0, 0.5 | Pricing fallbacks when no configured row exists |
| `DefaultJwtDuration` | 6360 hours | Full app JWT lifetime |

Other constants worth knowing live next to their code: the 24-hour tip window in `internal/service/ride/driver.go`, the 2-minute auto-queue minimum age in `internal/service/activation/activation.go`, pool sizes in `internal/data/repository/storage.go`, and cache TTLs in `internal/data/redis`. See [Pricing](/concepts/pricing) for how the pricing defaults are used.
