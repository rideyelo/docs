## Two identity systems

Yelo has two unrelated identity systems. They never share users.

| System | Who | Identifier | Issuer | Validated by |
| --- | --- | --- | --- | --- |
| App identity | Riders and drivers | `Users.id` (UUID) | Yelo API (HS256 JWTs) | `jwt.ValidateJwt` in `internal/utilities/jwt/jwt.go` |
| Dashboard identity | Admins, interns, fleet managers | Clerk user ID (`user_...`) | Clerk (RS256 session JWT) | `clerkAuthMiddleware` in `internal/server/http/clerk_middleware.go` |

A staff member who also rides has two separate accounts. Nothing in the API maps a Clerk user to a `Users` row. See [Dashboard identity with Clerk](/engineering/identity/dashboard-clerk).

## App sign-in surfaces

| Surface | Routes | Status |
| --- | --- | --- |
| Auth v3 | `/authv3/*` | Primary sign-up and sign-in for mobile and web. Mounted only when `AUTH_V3_ENABLED=true`. |
| Auth v2 phone OTP | `/authv2/phone/request-otp`, `/authv2/phone/verify-otp` | Still mounted. Used by the web `/delete-account` page. Issues full JWTs to complete v2 accounts. |
| Auth v2 email and OAuth | `/authv2/email/*`, `/authv2/community/*` | Used by the mobile school verification screens and the World Cup claim. |
| Auth v2 status | `GET /authv2/status` | The mobile `currentUser` query. Accepts presignup and full tokens. |
| Legacy v1 `/auth/*` | None | Not registered in `internal/server/http/router.go`. |

## Credential inventory

| Credential | Format | Lifetime | Where it lives on the client |
| --- | --- | --- | --- |
| Auth v3 request secret | HMAC-sealed envelope (`authv3-request-v1`) | Transaction TTL, default 10 minutes | URL fragment `#request=`, then SecureStore draft (mobile) or `sessionStorage` (web) |
| Provider state | HMAC-sealed envelope (`authv3-provider-v1`) | Provider start TTL, default 5 minutes | Round-trips through Google or Apple |
| Handoff code | 32 random bytes, base64url | Handoff TTL, default 2 minutes, capped at transaction expiry | Callback query `?code=` |
| Onboarding JWT | HS256, role `authv3_onboarding`, separate key | 15 minutes (app), 1 hour (web) | SecureStore draft |
| Native user JWT | HS256, role `user` | 6,360 hours | SecureStore key `session` |
| Web user JWT | HS256, role `user` | 1 hour | `sessionStorage` key `yelo_signup_jwt` |
| Web refresh token | 32 random bytes, rotating | 90 days idle, 365 days absolute | `__Host-yelo_refresh` cookie |
| Presignup JWT | HS256, role `presignup` | 1 hour | Mobile session or web `sessionStorage` |
| Stripe reauth JWT | HS256, role `user` | 24 hours | Query string of the Stripe onboarding return URL |
| Clerk session | RS256 | Clerk-managed | Clerk SDK |

Details are in [Tokens, sessions, and keys](/engineering/identity/tokens-and-sessions).

## Database tables

All Auth v3 tables were introduced in `migrations/000256_auth_v3_storage.up.sql` and later migrations. Opaque secrets are only stored as SHA-256 hashes (`HashOpaqueSecret` in `internal/service/authv3/security.go`).

| Table | Purpose | Retention |
| --- | --- | --- |
| `AuthTransactions` | One row per sign-in or link attempt. Holds hashes of the request secret, state, and nonce, the PKCE challenge, legal acceptance, coarse IP location, and status. | Deleted 30 days after `expires_at` if it has no handoff code |
| `AuthIdentities` | One row per linked login method. Unique on `(provider, provider_subject)` and on `(user_id, provider)`. Holds the encrypted Apple refresh token. | Deleted on account deletion |
| `AuthHandoffCodes` | One-time codes. Unique per transaction. | Deleted 24 hours after expiry or consumption |
| `AuthWebSessions` | Rotating browser refresh sessions, grouped by `family_id` | Never cleaned up by the runtime loop |
| `AuthPhoneAttempts` | One per transaction. Phone, HMAC bindings, send and verify counts, the OTP code at rest, Twilio SID, delivery status. | Deleted as soon as `expires_at` passes |
| `AuthRateLimitCounters` | Fixed-window counters keyed by `(scope, subject_hash)` | Deleted as soon as the window expires |
| `AuthDeniedSubjects` | HMAC of provider subjects that must never sign in again | Permanent |
| `UserLegalAcceptances` | Immutable per `(user_id, document, version)` | Cascades with the user |
| `AttributionTouches`, `UserAttribution` | Anonymous acquisition touches, bound to a user after sign-in | Kept after account deletion. `user_id` is only nulled if the `Users` row is hard-deleted. |
| `EducationVerifications` | School proofs by provider | Kept after account deletion |
| `StudIDVerificationAttempts` | Encrypted StudID secret per attempt | Not cleaned up |

The runtime cleanup loop is described in [Auth v3 transaction lifecycle](/engineering/identity/auth-v3-transactions#cleanup).

## Keys and secrets

Never log or paste these values. The table lists names and rules only.

| Env var | Used for | Rotation model |
| --- | --- | --- |
| `KEY` | Signs every app user and presignup JWT | Move the old value to `KEY_LEGACY`. Validation tries `KEY`, then each legacy key, only on signature failure. |
| `KEY_LEGACY` | Comma-separated verification-only keys | Remove after the longest live token (6,360 hours) has expired |
| `AUTH_V3_ONBOARDING_JWT_KEY` | Signs onboarding tokens | No legacy list. Rotating it invalidates in-flight onboarding tokens (15 minutes). |
| `AUTH_V3_STATE_HMAC_KEYS` | Seals request secrets and provider state; derives attempt nonces | Newest first. Every key verifies. Rotating the first key changes derived nonces, so in-flight attempt retries get `409`. |
| `AUTH_V3_SUBJECT_HMAC_KEY` | Addresses `AuthDeniedSubjects` | Rotation orphans every tombstone. Requires a data migration. |
| `AUTH_V3_RATE_LIMIT_HMAC_KEY` | Pseudonymizes phones and IP prefixes in counters and attempts | Rotate only after counters from the old key expire (at most 1 hour) |
| `AUTH_V3_REFRESH_TOKEN_KEYS` | AES-256-GCM for Apple refresh tokens and StudID secrets | Newest first. Each ciphertext carries an 8-byte key ID. Never drop a key while ciphertexts use it. |

`hmacKeySeparationProblems` in `internal/utilities/config/authv3.go` refuses to start the API if any of these keys are shorter than 32 bytes, equal each other, or equal `KEY`, a `KEY_LEGACY` entry, the Google client secret, the Apple private key, or the Twilio auth token.

## Gotchas and edge cases

- **Two tokens with the same role, very different lifetimes.** Native and web user tokens are both role `user` signed with `KEY`. The API can't tell them apart. Only the `exp` claim differs.
- **Auth v3 off does not turn Auth v2 off.** Auth v2 phone OTP remains a full sign-in path for accounts that have a phone, an email, and a finished profile. It shares Auth v3's rate limiter only when Auth v3 is enabled. See [Phone OTP and abuse controls](/engineering/identity/phone-otp-and-rate-limits#auth-v2-legacy-limits).
- **Web sessions are not garbage collected.** `DeleteExpiredAuthV3RuntimeState` cleans transactions, handoffs, phone attempts, and counters, but never `AuthWebSessions`.
- **The subject HMAC key is effectively permanent.** Rotating `AUTH_V3_SUBJECT_HMAC_KEY` silently un-bans every banned provider subject.
