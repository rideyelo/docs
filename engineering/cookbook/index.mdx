## Conventions every recipe assumes

- Branch from `main`. Run each repository's full gate before you push: `make check` in `yelo-api` and `yelo-frontend`, and `pnpm check` in `yelo-web`.
- Commit generated output with the change that caused it. This covers sqlc, mocks, `openapi.json`, the consumer lock files, and Orval output. CI regenerates each one and fails on any diff.
- For a cross-repo change, merge and release the API first, then the clients. PR descriptions link their companion PRs and state any required non-code configuration.
- Describe migrations, breaking changes, and trigger or secret changes in the PR description. Reviewers and the release owner rely on it.
