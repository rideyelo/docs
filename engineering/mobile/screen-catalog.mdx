This is the route-by-route reference for `app/`. Each entry lists what the screen renders in each state, the API it calls directly (generated hooks resolve to the paths shown), where it goes next, and what can redirect it away.

[Navigation](/engineering/mobile/navigation) explains the route groups, guards, and deep links. The flow pages go deeper on behavior: [Rider experience](/engineering/mobile/rider-experience), [Driver experience](/engineering/mobile/driver-experience), [Social and contacts](/engineering/mobile/social-and-contacts), and [Auth and onboarding](/engineering/mobile/auth-and-onboarding).

<Note>
Paths below drop route groups the way URLs do, except where the group matters for `router.push` targets. "Status redirects" means `StatusGuard` (drivers to `/drive`) and `useRideLifecycleNavigation` (riders by ride status) can move the user away. Both leave `/scan-qr` and `/tip/` alone, and `StatusGuard` also leaves `/fleet-join/`.
</Note>

## Auth

| Route | Purpose and states | Data | Exits and guards |
| --- | --- | --- | --- |
| `/(auth-v3)` (`index`) | Entry with parallax background and dither reveal. **Get Started**. After a browser cancel, "Having trouble? Continue in app". Repeated taps reveal the version and update id. | `POST /authv3/authorize` (prefetched) | Hosted web page, or `method` on fallback. |

## Gotchas and edge cases

- **The drive guard is a substring check.** `StatusGuard` tests `pathname.includes('/drive')`, which also matches `/driver-earnings`, `/driver-signup`, and `/driver-marketing`.
- **The World Cup prompt can interrupt a ride.** `(app)/_layout.tsx:72` skips only `/tip/` paths before pushing `post-signup/14-student`.
- **`ride/*` legacy routes are reachable by URL.** `com.rideyelo://ride/pickup` still opens the old pickup screen because `+native-intent` passes unknown paths through.
- **The Stripe return URL points nowhere.** `lib/payments/paymentSheetConfig.ts:80` returns to `ride/2-select-ride`, which has no route file.
- **The approval push targets a missing route.** The API's `driver_application_approved` push deep-links to `/driver-signup/1-application-status`. See [Driver onboarding](/concepts/driver-onboarding#admin-review).
- **Deals ignore their id.** Any event tagged `deal` opens the same hard-coded deal page.
- **`ride-details` depends on a cached list.** A ride outside the latest 200 history rows renders "Ride not found".
- **`events/[eventId]` is the only `(app)` route with a vertical dismiss gesture.** Every other full-screen route either disables gestures or uses the horizontal default.
- **Labs redirect silently.** Opening `glass-lab`, `color-lab`, or `design-system-lab` by URL without the experiment lands on settings with no message.
- **`driver-earnings` sub-screens bounce.** For fleet-managed drivers, `2-all-activity` replaces to drive history and `3-all-payouts` replaces to the earnings hub, so the two "see all" links behave differently.
