Use this page to answer "what does this screen actually call, how often, and who is allowed to?" Each section follows one route from [Dashboard architecture](/engineering/web/dashboard-architecture): the component that issues the request, the generated operation, the `yelo-api` registration, the service method, and the refresh behavior.

Paths are relative to the repo root: `yelo-web/src/...` for the frontend and `yelo-api/internal/...` for the API. Generated hooks live in `src/generated/dashboard/endpoints/<tag>/<tag>.ts`. The hook name is the operation ID with the tag prefix camel-cased, so `useCommunityGetMarketKPIs` is operation `community.GetMarketKPIs`.

## How a dashboard request is authorized

Every `/dashboard/*` request passes four layers. A request can fail at any of them, and they return different status codes.

| Layer | Where | Behavior |
| --- | --- | --- |
| Clerk session | `server/http/clerk_middleware.go` (`clerkAuthMiddleware`) | Verifies the bearer token and reads `metadata.role`, `community_id`, and `fleet_assignments` from the **session token claims**. Missing claims → `401` with an empty envelope. |
| Scope allowlist | `server/http/dashboard_scope.go` (`dashboardScopeAllows`) | Path-based allowlist for `intern` and `fleet`. Anything not listed → `401`, even if the handler would allow it. Admins pass everything. |
| Group role gate | `server/http/router.go` `registerDashboardRoutes` | `getRequireClerkRoleMiddleware` on `/dashboard/users/*` (admin), `/dashboard/notifications/*` (admin), `/dashboard/leads/drivers/*` (admin, intern), `/dashboard/education-claims/*` (admin). Wrong role → `403`. |
| Handler check | Individual handlers | `Role != roleAdmin` checks or `ResolveDashboardCommunity` / `HasFleetAccess`. Usually returns a `403` error envelope. |

The full allowlist is documented in [API authentication](/engineering/api/authentication). The UI never relies on status codes for gating; it hides controls with `useRole()`, so a mismatch shows up as an inline error or an empty table.

<Note>
One endpoint that every page uses is **not** a dashboard route. `useCommunityGetAllCommunities` calls `GET /community/`, registered by `community.RegisterUnauthenticatedRoutes` (`server/http/community/community_router.go:52`). It is public, served from the Redis `communities:all` cache with a 60-second TTL (`data/redis/community_cache.go`), and returns every community including test communities. Role filtering happens in the browser.
</Note>

## Home and KPI

`/` renders `RootRoute`, which redirects `admin` to `/live`, `intern` to `/community`, and `fleet` to `/fleets`. It issues no queries.

| Route · component | Hook | Endpoint | API handler → service | Refresh |
| --- | --- | --- | --- | --- |
| `/kpi` · `OrgKpiCards`, `KpiCharts` | `useDashboardGetGlobalKPIs` | `GET /dashboard/kpi/global` | `dashboard/kpi/handlers.go:44` → `KpiService.GetGlobalKPIs` | Default. Both components share one query key, so one request. |
| `/kpi` · `AcquisitionBreakdown` | `useDashboardGetAcquisitionBreakdown` | `GET /dashboard/kpi/acquisition` | `kpi/handlers.go:59` → `KpiService.GetAcquisitionBreakdown` | Default |

All KPI handlers call `requireAdmin` (`kpi/handlers.go:28`). `GetMarketKPIs`, used by `/rides`, `/community`, and `/fleets`, runs four queries: `GetDashboardMarketMetrics` and `CountDashboardSearches` for the current window and again for the previous window (`service/dashboard/dashboard.go`). `calculateTimeRanges` handles `last_24_hours`, `last_7_days`, `last_14_days`, `last_30_days`, and `all_time`; anything else becomes seven days, but `GetKPIsRequest.Validate` rejects other values with `400` first.

## Users (`/users`)

`UsersPage` uses a `useInfiniteQuery` keyed `['users-directory', scope, community, search, type, tag, sorting]` with 100-row pages, 60 s stale, and 10 min gc. Admins call `dashboardGetUsersGlobal` (`GET /dashboard/users`, handler `dashboard/users/handler.go:130`); interns call `usersGetUsers` (`GET /dashboard/{id}/users`, `community_handler.go:769`). The search input is debounced 300 ms.

`UserDetailSheet` returns `null` for non-admins, so interns can browse the table but cannot open a user. For admins it loads `GET /dashboard/users/detail/{id}`, `GET /dashboard/fleets`, `GET /dashboard/users/detail/{id}/notifications?limit=20`, and, in `UserQuo`, `GET /dashboard/users/detail/{id}/messages` (30 s stale, no focus refetch). Mutations: tags, test status, profile, fleet assignment, and move to Yelo, all under the admin-gated `/dashboard/users` group.

## Live (`/live`)

For the API side of this page, see [Live operations internals](/engineering/domains/live-operations).

`LivePage` has no tabs. The selected market is the shared `CommunityContext` selection, and `period` and the rides filter are local state, so neither is in the URL. `/presence` and `/driver-ops` redirect here. `/supply-demand` has no route and renders the **Coming Soon** fallback.

Queries use `useLiveData` (`components/live/useLiveData.ts`) or `hooks/useLive.ts`. `staleTime` equals the poll interval, `gcTime` is 5 minutes, and `retry` is 1.

## Gotchas and edge cases

- **Role changes lag.** The API reads role and assignments from Clerk session token claims, not from the Clerk API. After someone edits a user on `/access`, that user keeps their old scope until Clerk refreshes their token, even though `DashboardSession` remounts on the new `publicMetadata`.
- **`401` means "outside the allowlist", not "signed out".** `dashboardScopeAllows` answers `401` for interns and fleet managers who hit a route not on their list. Check `dashboard_scope.go` before debugging Clerk.
- **Rides always poll fast.** `HasActiveDashboardRides` treats any ride that is not `complete` and not canceled as active, with no time bound (`analytics.sql:954`). Stale `no_drivers_available` or `pending_rider_rating` rows keep `has_active` true, which keeps the Trips tab on the 10-second interval. Every **Live** ride poll also pays for this `EXISTS` scan.
- **Feed ad cards cannot load.** `FeedPreview` calls `GET /ad/{id}`, which sits in the app-JWT group (`router.go:186`). The dashboard's Clerk token fails there, so ad cards fall back to the "Ad" placeholder. `GET /ride/{id}` works because its optional-auth middleware ignores tokens it cannot parse.
- **Tabs are not all URL-backed.** `/rides`, `/drivers`, `/manage`, `/communities`, and `/notifications` persist their tab in the query string. `/fleets`, `/events`, and `/access` do not, so deep links always open their first tab. **Live** keeps its period and rides filter in local state.
- **`/supply-demand` bookmarks break.** `/presence` and `/driver-ops` redirect to `/live`, but `/supply-demand` falls through to **Coming Soon**.
- **Invalid `community_id` on telemetry means global.** The handler ignores an unparseable ID and returns org-wide numbers instead of an error.
- **Community list includes test communities.** `GET /community/` is unfiltered, so the sidebar dropdown, **Live** market cards, and `CommunityFilterDropdown` show active test markets to admins. **Live** analytics exclude test communities, so a test market card shows live rides but zero performance numbers. `CommunityFilterDropdown` also does not filter by role.
