Three `yelo-web` sites need no sign-in and aren't part of sign-up: `world-cup`, `home`, and `maestro`. [Sites](/engineering/web/sites) lists what each one is for. This page covers how each one works, what it calls, and what a crawler or analytics tool sees. For domains and Workers in front of them, see [Edge and routing](/engineering/web/edge-and-routing). The invite, fleet invite, and event landings are on the `signup` site; see [Signup and Auth v3 site](/engineering/web/signup-and-auth-site).

## At a glance

| Site | Bootstrap | Router | Data | Link preview tags | Analytics |
| --- | --- | --- | --- | --- | --- |
| `world-cup` | `renderSite(<LandingV5 />)`, no providers | None | `GET /world-cup/standings`, `GET /world-cup/activity` through `/world-cup/api` (offline: the Worker now redirects that path) | `<meta name="description">` only | None |
| `home` | Plain `createRoot` | Custom pathname switch | None, except `POST /authv3/attribution/touch` on attributed visits | Full `og:*` and `twitter:*`, plus per-route static HTML | None |
| `maestro` | `renderSite(<App />, {})`, no providers | Query params: `?view=screens\|flows\|runs\|previews`, `?run=` | Supabase Storage JSON | None | None (the Auth v3 entry reuses signup's PostHog gating) |

## world-cup

A single-page campus race built for the `/world-cup` path on `rideyelo.com` and `joinyelo.com`. The campaign is offline: the `world-cup-router` Worker now redirects `/world-cup*`, including `/world-cup/api`, to `https://joinyelo.com/`, so the page and its data loop below aren't reachable on the public domains. See [Edge and routing](/engineering/web/edge-and-routing#world-cup-router). `tools/vite/base/config.ts` sets `base: '/world-cup/'` and nests output in `dist/world-cup/world-cup/`.

### Data loop

`hooks/useWorldCupStandings.ts` owns all data. It does not use React Query.

| Step | Call | Detail |
| --- | --- | --- |
| Standings | `worldCupGetStandings` with `url: ${BASE_URL}api/standings` and `baseURL: ''` | Same-origin. While the campaign ran, the `world-cup-router` Worker proxied it to `api.rideyelo.com/world-cup/standings`. The Worker now redirects the path instead. The API sets `Cache-Control: public, max-age=10, stale-while-revalidate=30`. |
| Backlog drain | `worldCupGetActivity` with `after` cursor, `limit=50` | Runs once, up to 60 pages. Seeds the ticker without firing map pings. The cursor commits only after the full drain succeeds. |
| Live poll | Same activity call from the saved cursor | Every 15 s and on `visibilitychange` to visible. Skipped while hidden or while another fetch is in flight. API cache header: `max-age=5, stale-while-revalidate=15`. |
| Staleness | — | Two consecutive failures set `isStale`. |

`lib/worldCup.ts` defines `WORLD_CUP_CAMPUSES`, the official race list, and `BACKGROUND_SCHOOLS`. Standings match campuses by email domain against each API school's `extensions`, including subdomain matches. Totals, ticker events, and map pings count only listed campuses; background schools only get map dots. A campus `baseline` is subtracted from its claim count.

The claim CTA points at `VITE_SIGNUP_URL`, defaulting to `https://joinyelo.com/world-cup/claim` (`lib/brand.ts:19`), which the signup site handles.

### Styling

Fonts load from `api.fontshare.com` (Switzer) and Google Fonts (Instrument Serif, Inter, Space Mono, Caveat) in `index.html`. The site has its own `public/` with the US map TopoJSON (`us-nation-10m.json`) and artwork.

## home

The marketing site for `joinyelo.com`. It skips Tailwind, `renderSite`, and React Router; read [Home site](/engineering/web/home-site) before editing.

### Routing

`main.tsx` normalizes the pathname (trailing slashes removed, lowercased) and renders one of seven lazy pages. `navigation.ts` provides client-side navigation for `/`, `/drivers`, `/safety`, `/vision`, `/fleets`, and `/partner`. Any other same-origin link does a full page load. Unknown paths render the rider landing, because Firebase's `**` rewrite serves `index.html`.

| Path | Component | Nav variant |
| --- | --- | --- |
| `/` | `NewLanding` with rider content | `rider` |
| `/drivers` | `NewLanding` with `content/driver.tsx` | `driver` |
| `/partner` | `partner/PartnerPage` | none |
| `/fleets` | `fleets/FleetsPage` | none. The coverage map is generated by `scripts/gen-fleets-map.mjs`. See [Web build helpers and fixtures](/engineering/web-extra/tooling-and-fixtures) |
| `/safety` | `safety/SafetyPage` | none, dark |
| `/vision` | `vision/VisionPage` | none |
| `/privacy`, `/tos`, `/terms` | `legal/LegalPage` with `legalContent.ts` | Nav hidden |

`/farefinder` is not in this table. It is a static page in `public/farefinder/` that Vite copies into `dist/home` as-is, and Firebase serves it before the `**` rewrite, so `main.tsx` never runs there. Its assets are namespaced under `/farefinder/`, and every call to action goes through `https://yelo.link/aggregator` (a 302 to the App Store) for attribution. See [Sites](/engineering/web/sites#home).

`prepareRoute()` sets `data-page` and `data-variant` on `<html>`, adds route-specific motion classes, and updates `<title>`, `description`, `og:title`, and `og:description` at runtime.

### Link previews

Crawlers do not run JavaScript, so runtime titles are invisible to them. The `home` build target runs `scripts/emit-partner-html.mjs` after `vite build`. For each entry in its `PAGES` list (`partner`, `fleets`, `safety`, `vision`, `drivers`, `privacy`, `tos`, `terms`), it copies `dist/home/index.html` into `dist/home/<route>/index.html` with a new `<title>`, `description`, `og:title`, `og:description`, and `og:url`. Entries with an `image` also replace `og:image` and `twitter:image`: `partner`, `fleets`, `safety`, and `vision` use the `og` Worker's `page` card, and `drivers` uses its `drive` card. The legal pages keep the home card. The `/safety` copy also preloads its hero image per viewport. Every substitution is asserted, so renaming a meta tag in `index.html` fails the build. Firebase rewrites each route to its own file.

The base document sets `og:url` to `https://joinyelo.com/`, the single source for the origin, and `og:image` to the signed `page` card `https://joinyelo.com/og/page?r=home&sig=...` (1200×630). `public/farefinder/index.html` points at the `farefinder` card. Titles read as subject lines, such as "Get out there with Yelo", "Fill your venue with Yelo", and "Drive with Yelo and keep 100% of every fare", rather than `Yelo | <Page>`. For the templates, see [og](/engineering/web/edge-and-routing#og).

### Contact and forms

`contact.ts` is a module-level store: any `contact` link calls `openContact()` and the singleton `ContactModal` mounted in `HomeApp` opens. Phone, SMS, email, careers (Notion), and partner intake (Typeform) URLs are constants in the same file. There is no API call and no analytics script on this site.

## maestro

An internal viewer for the product inventory and for end-to-end runs. It reads static JSON and media, not the Yelo API. The dashboard embeds the same `App` at `/inventory`; see [Inventory](/dashboard/inventory) for the operator view.

| File | Role |
| --- | --- |
| `types.ts` | `ARTIFACT_ROOT` is `VITE_E2E_ARTIFACT_BASE_URL` or `VITE_SUPABASE_URL/storage/v1/object/public/e2e`. Runs live at `runs/<id>/`. |
| `App.tsx` | Picks the view from the query string: `?run=<id>` renders `RunViewer`, `?view=runs` renders the run list, `?view=previews` renders `LinkPreviews` (the `og` Worker's committed card snapshots), and anything else renders `Inventory` on `screens` or `flows`. Fetches `index.json` with a 15-second timeout. The run list filters by `passed` or `failed` and sorts pinned runs first. Pins persist in `localStorage` key `e2e-report:pins`. |
| `ViewerHost.tsx` | Context with `embedded` and `navigate`. Standalone, `navigate` calls `history.pushState` or `replaceState`. The dashboard's `InventoryPage` supplies React Router's `navigate` and sets `embedded`, which stops the viewer from setting `document.title` and hides the footer theme toggle. |
| `useInventory.ts` | Fetches `inventory/catalog.json` from `ARTIFACT_ROOT`. A `404` falls back silently to the bundled `product-catalog.json`; any other failure falls back with a **Using bundled inventory** notice. Then loads every run manifest, four at a time. |
| `evidenceCache.ts` | Caches parsed run manifests for five minutes in memory and in Cache Storage (`yelo-maestro-evidence-v1`, at most 100 entries). The key includes the run's status, start time, duration, commit, and counts from the index. **Refresh evidence** bypasses it. |
| `inventory.ts` | Zod schemas for the catalog and for run evidence, plus the classification rules. See [Evidence status](#evidence-status). |
| `ProductInventory.tsx` | The inventory UI: revision strip, coverage meters, filters, screen gallery, and screen and flow details. Selection (`screen`, `variant`, `flow`, `case`) and scope (`platform`, `role`, `internal`, `api`) live in the query string. |
| `FlowSeries.tsx`, `series.ts` | The step-by-step picture strip per role and the Mermaid flowchart for a flow case. `mermaid` is imported lazily and rendered with `securityLevel: 'strict'`. |
| `CaptureImage.tsx`, `imagePreview.ts` | Loads an image only within 240 px of the viewport. Uses the WebP thumbnails a manifest lists under `thumbnails/<sha256>/` when they match the original's hash; otherwise asks Supabase's image render endpoint for 360 and 720 px previews, then falls back to the original PNG. |
| `RunViewer.tsx` | Loads `runs/<id>/manifest.json`, lists executions per device role, plays the MP4, and seeks the video when you click a timeline event. `?execution=<testId>:<role>` selects an execution and `&t=<seconds>` seeks to a time. When an execution has a `manifestPath`, it also fetches that role's own manifest and uses its timeline, `startedAt`, and tests, so offsets line up with that role's recording. Until the role manifest loads, timeline seeks are disabled; if it fails, the viewer shows "Execution timing unavailable. Showing published events." A failed execution shows **Execution failed**, with `· replay-failed` when a test failed with that message. |
| `evidenceLog.ts` | Parses NDJSON timing records into a step log with offsets. `timelineEvidenceEntries()` projects manifest timeline events into the same shape (type, step command and index, pass or fail, duration) and never recovers log details, selectors, or error payloads. The **Action log** uses these entries when a run has no `replay-timing.ndjson`, labeling rows `S<step>` instead of `L<line>`. |
| `WorkflowCoverage.tsx` | Renders the declared-workflow coverage report. |
| `ThemeToggle.tsx` | Stores `theme` in `localStorage`. |

### Evidence status

`classify` in `inventory.ts` gives each capture or recording one status. Only `current` earns coverage.

| Status | Rule |
| --- | --- |
| `failed` | The scenario is missing, failed, or has an error, or any device role's execution did not pass. |
| `historical` | The run's app `sourceTreeSha256` differs from the catalog's, the run's `inventoryEvidence.catalogHash` is not the catalog's hash, or the capture is not declared in the run's `inventoryEvidence`. |
| `unverified` | Build, runner, or API provenance is missing, dirty, or inconsistent between the run and its roles; an execution has a non-zero exit code, evidence errors, or a test with `attempts` other than 1; the screenshot is missing; or, for a flow, a required role or its single MP4 is missing. |
| `current` | None of the above. |
| `missing` | No evidence. The UI labels it **Not captured**. |

Within one screen state, role, and platform, the newest run wins, so an older passing run can't hide a newer failure. Redirect screens are excluded from coverage totals. With an `api` filter set, runs against any other API revision are dropped before classification.

<Note>
The catalog schema pins `source.repository` to `rideyelo/yelo-frontend`, and `src/sites/maestro/README.md` describes a registry and publish target in that repository. Both exist on `yelo-frontend` `main`: the registry is `e2e/inventory/product.json`, `make inventory-publish` uploads `inventory/catalog.json`, and each run manifest carries `inventoryEvidence`. Publishing is a manual step, and no workflow runs it. Until someone publishes a catalog, the viewer shows the bundled snapshot, and a run can classify as `historical` or `failed` but not `current`. See [Product inventory](/engineering/qa/e2e#product-inventory).
</Note>

The second entry, `auth/v3/index.html`, mounts the signup `AuthV3Page`. The Nx build target sets `VITE_API_URL=$VITE_E2E_API_URL` and `VITE_AUTH_V3_APP_SCHEME=com.rideyelo.e2e` so E2E app builds sign in against the E2E API and return to the E2E app.

## Gotchas and edge cases

- **Crawler titles must be kept in two places.** `PAGES` in `emit-partner-html.mjs` and `prepareRoute()` in `home/main.tsx` duplicate every title and description. A route missing from `PAGES` still works for readers but shares the landing's card.
- **Card URLs carry fixed signatures.** The `og:image` URLs in `home/index.html`, `public/farefinder/index.html`, and the emit scripts are signed with `OG_SIGNING_SECRET`. Rotating the secret breaks every one of these previews until you re-sign them.
- **Case matters to Firebase, not to `home`.** `/Partner` normalizes to `/partner` in `main.tsx`, but Firebase rewrites are case-sensitive, so a crawler gets the landing document.
- **World Cup polls pause when hidden.** Both the 15-second interval and the visibility handler check `document.visibilityState`, so background tabs never poll.
- **Maestro's CSP is narrower than signup's.** `maestro/firebase.json` allows `connect-src` only to `'self'`, `*.run.app`, and PostHog. `VITE_E2E_API_URL` must be a Cloud Run URL, and a relative value would fall back to `api.joinyelo.com`, which the CSP blocks.
