This page catalogs the building blocks that dashboard pages share. Reach for these before writing a new table, map, or dropdown. [Dashboard architecture](/engineering/web/dashboard-architecture) covers the provider tree, routing, roles, and community scope; [Add a dashboard page](/engineering/web/adding-a-dashboard-page) shows how the pieces fit into a new route.

Components reused across pages live in `src/components/`, grouped by domain. Components used by one dashboard page live in `src/sites/dashboard/components/`. shadcn primitives live in `src/components/ui/`.

## shadcn primitives

`src/components/ui/` contains `accordion`, `alert-dialog`, `avatar`, `badge`, `button`, `card`, `chart`, `collapsible`, `command`, `dialog`, `dropdown-menu`, `input`, `label`, `popover`, `radio-group`, `select`, `separator`, `sheet`, `sidebar`, `skeleton`, `switch`, `table`, `tabs`, `textarea`, and `tooltip`, plus the `use-mobile` hook. Add new primitives with the shadcn CLI (`components.json`) rather than copying them from another project.

## Tables

### appTableFeatures

`src/lib/table.ts` exports one TanStack Table v9 feature set, `appTableFeatures`, and its type `AppTableFeatures`. It enables column sizing, column visibility, row pagination, row selection, row sorting, a sorted row model, and four sort functions: `alphanumeric`, `basic`, `datetime`, and `text`. 27 files use it. Keep new tables on the same set so column definitions stay type-compatible:

```tsx
import { useTable, type ColumnDef } from '@tanstack/react-table';
import { appTableFeatures, type AppTableFeatures } from '@/lib/table';

const columns: ColumnDef<AppTableFeatures, Row>[] = [/* ... */];
const table = useTable({ features: appTableFeatures, data, columns, state: { sorting }, onSortingChange: setSorting });
```

### Pagination strategies in use

| Strategy | Example | How |
| --- | --- | --- |
| Server offset paging | `RidesTab` | `pagination` state maps to `limit` and `offset` query params; **Next** disables at `total`. Filters and search reset `pageIndex` to 0. |
| Infinite scroll with virtualization | `UsersPage` | `useInfiniteQuery` pages of 100, `getNextPageParam` from `total_count`, and `useVirtualizer` from `@tanstack/react-virtual` |
| Client table with load-more | `ActivityTable` | Virtualized, 52 px estimated rows, `overscan: 8`, optional `onLoadMore` and `hasNextPage` |
| Fully client-side | Most configuration tables | Load everything, sort with `appTableFeatures` |

### ActivityTable

`src/sites/dashboard/components/ActivityTable.tsx` is the closest thing to a generic data table. `RecentSearchesTable` and `IssuesAnalyticsTab` use it.

| Prop | Type | Purpose |
| --- | --- | --- |
| `label` | `string` | Accessible name |
| `columns` | `ActivityColumn[]` (`key`, `header`, `cell(row)`, `size`) | `size` defaults to 170 |
| `data`, `loading`, `emptyLabel` | — | Rows and states |
| `rowKey` | `(row, index) => string` | Becomes `getRowId` and the virtual item key |
| `onRowClick` | optional | Row activation |
| `totalCount`, `hasNextPage`, `fetchingNextPage`, `onLoadMore`, `loadError` | optional | Infinite loading |

Its search box filters only string fields of the rows already loaded, and sorting is local.

### URL-backed state

Prefer query parameters for anything a teammate might link to. Existing conventions:

| Parameter | Pages | Meaning |
| --- | --- | --- |
| `tab` | `/rides`, `/drivers`, `/manage`, `/communities` | Active tab |
| `notification_tab` | `/notifications` | Active tab |
| `community`, `scope` | `/rides`, `/pricing`, `/communities`, `/drivers` | Admin market scope, or the community to open |
| `status`, `fleet`, `older`, `ride_id` | `/rides` | Trips filters and the open ride sheet |
| `range` | `/rides` | Issues tab time range. **Live** links set it. |
| `user` | `/users` | Open user sheet |
| `lead`, `user`, `userId` | `/drivers` | Open lead, or jump to the drivers tab |
| `fleet` | `/manage` | Open fleet (also `/manage/:fleetId`) |
| `section` | Any | One-time scroll target from global search; consumed and removed |

Write them with `setSearchParams((current) => { const next = new URLSearchParams(current); ... }, { replace: true })` so other parameters survive and filter changes do not flood history.

## Sheets and dialogs

Detail and edit surfaces use the shadcn `Sheet` from the right. The recurring shape:

1. The parent owns the selected ID, ideally in the URL.
2. The sheet receives `id`, `isOpen`, and `onClose`, and enables its queries with `enabled: isOpen && !!id`.
3. Mutations call `invalidateQueries` on the list key and show `toast.success` or `toast.error(getApiErrorMessage(...))`.

| Kind | Examples |
| --- | --- |
| Read-mostly detail | `UserDetailSheet`, `RideDetailSheet`, `FleetDetailSheet`, `NotificationDetailSheet`, `DriverApplicationReviewSheet`, access detail sheets |
| Forms with `react-hook-form` + `zod` | `PricingConfigSheet`, `SendNotificationSheet`, `MarketingSegments` |
| Forms with local state | `FleetFormSheet`, `SchoolFormSheet`, `EventFormSheet`, `SpotFormSheet`, `LocationFormSheet`, `VehicleTypeFormSheet`, `InviteUserSheet` |
| Confirmations (`AlertDialog`) | `CommunityDeleteDialog`, `CancelNotificationDialog`, `SilentCancelRide`, `UserFleetMemberships`, and inline confirms in `ManageFleetsPage`, `FleetDriverJoinLinkCard`, `SurgeSlider`, `UserDetailSheet`. `NotifyMarketDialog` and `PingDialog` in `components/live/` have no routed caller. |

`UserDetailSheet` is a role wrapper: it renders nothing unless `useRole().isAdmin`, then mounts `AdminUserDetailSheet`. Follow that pattern when a sheet's endpoints are admin-only, so interns never fire requests that the API rejects.

### Writing a layer hook

The community map splits every layer into a hook with the same signature: `{ mapRef, styleReady, visible, ...data }`. Follow `useZonesLayer.ts`:

- Add the GeoJSON source and layers only when `styleReady` is true and `map.getSource(id)` is empty.
- Update data with `setData` in a separate effect keyed on the data.
- Toggle `visibility` layout properties instead of removing layers.
- In cleanup, check `isMapRemoved(map)` (`mapLifecycle.ts`) before touching the style. The map may already be destroyed when a route unmounts.
- Fetch the layer's data in the page with `enabled: visible` so hidden layers cost nothing. Add the layer to `LayerKey` and `DEFAULT_LAYER_VISIBILITY` in `types.ts`.

Dark-mode popup styles live in `src/sites/dashboard/styles.css`.

## Global search and the command palette

`GlobalSearch` (`src/sites/dashboard/search/GlobalSearch.tsx`) is a `cmdk` `Command` with `shouldFilter={false}`; ranking happens in `search.ts`.

- **Shortcut.** Cmd+K or Ctrl+K toggles it.
- **Entries.** The build-time `virtual:dashboard-search-index` (pages and sections), role-allowed communities, fleets found in the React Query cache under `/dashboard/fleets` or `/dashboard/{id}/fleets` keys (admins), users already loaded by the `users-directory` query, and live user results from `GET /dashboard/users?search=` (admins, 300 ms debounce, 15 results).
- **Ranking** (`searchDashboard`). Text is NFKD-normalized, lowercased, and split on non-alphanumerics. An exact title match scores 100, a title substring 50. Each query token must match some word: exact 12, prefix 9, substring 5 (tokens of three or more characters), or an edit distance of 1 (2 for tokens of eight or more characters) with adjacent transpositions counted as one edit, for tokens of four or more characters. Tokens found in the title earn 8 more. Any unmatched token drops the entry. Results are capped at 24, ties sorted by title.
- **Navigation.** Selecting an entry with a `communityId` switches the global community first. Section results carry `?section=`, which `SearchNavigation` resolves to an element whose `id` or `data-search-section` matches, or to a heading whose slug matches. It waits up to 10 seconds for lazy content, scrolls with a 6 rem margin, focuses the target, then removes `section` from the URL.

The same `cmdk` primitive powers `TagCombobox` and `NotificationFilterSelect`.

## Gotchas and edge cases

- **`CommunityFilterDropdown` lists every community.** It calls the public `GET /community/` and does not filter by role or hide test communities. It is safe today only because `TelemetryPage` is admin-only.
- **`getApiErrorMessage` prefers developer text.** API envelopes carry `message`, `title`, and user-facing `body`. The helper returns `message` first and never reads `body`, so toasts can show technical wording. `TipStep` and `EduClaimStep` read `body` directly.
- **The `/manage` tab setter replaces the query string.** The list view's tabs call `setParams({ tab })`. That list only renders when no fleet is open, so no `fleet` parameter is lost today, but any parameter you add to the list view will be.
- **Dead page modules linger.** `OverviewPage` and `DriverOpsPage` have no route. `OverviewPage` is still in `routeImporters` under `/`, so it's still bundled as a chunk and indexed for global search. `DriverOpsPage` is only type-checked.
- **Search indexing depends on static copy.** Headings built from variables or placed inside tabs, sheets, or dialogs are not indexed. See [Add a dashboard page](/engineering/web/adding-a-dashboard-page).
- **`RecentViews` resets on reload.** It is component state only.
