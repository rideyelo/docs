## Script catalog

| Script | Run | Purpose |
| --- | --- | --- |
| `scripts/build-partner.mjs` | `node scripts/build-partner.mjs` | Builds the `home` site: `vite build` with `SITE=home`, then `scripts/emit-partner-html.mjs`. It stops on the first failing step and doesn't typecheck |
| `scripts/gen-fleets-map.mjs` | `node scripts/gen-fleets-map.mjs` | Regenerates `src/sites/home/public/map/us-growth-map.svg`, the coverage map on `/fleets` |
| `tools/testing/schools/` | `pnpm exec vite --config tools/testing/schools/vite.config.ts` | Standalone fixture for the dashboard school-management UI |
| `tools/vite/home/gen-home-images.ts` | `pnpm images:home` | Home-site responsive images. See [Public sites](/engineering/web/public-sites) |
| `scripts/notify-deploy-slack.sh` | CI | Resolves the merged PR for the deployed commit and posts the web or worker deploy alert to `SLACK_WEBHOOK_URL`. Skips with a warning when the secret is unset |
| `scripts/format-deploy-slack.sh` | CI | Formats the two-line **Web deployed** or **Worker deployed** Slack message, selected by `DEPLOY_KIND`. Tested by `pnpm test:deploy-slack` |
| `scripts/og-worker-smoke.sh` | CI, or locally | Renders six invite cards concurrently through `yelo-og` in workerd and fails unless every response is a PNG |

## Home-site build wrapper

`build-partner.mjs` exists for a hosting config whose build command is a plain string with nowhere to set `SITE`. Its header names `vercel.json` as the caller, but no `vercel.json` is committed to the repository. The Firebase deploy path in [Deployment](/engineering/deployment) doesn't use it.

The order matters: `emit-partner-html.mjs` reads `dist/home/index.html` and writes one document per route next to it. Running it first throws on the missing file.

## /fleets coverage map

The `/fleets` page shows a static SVG, referenced with an `<img>` tag, rather than drawing the map at runtime. `gen-fleets-map.mjs` produces it once:

1. Fetch the `us-atlas@3` states topology from jsDelivr.
2. Project with `geoAlbersUsa` (scale 1300) and draw the nation outline and interior state borders at 1-decimal precision.
3. Plot each entry in the script's `cities` list as a dot sized `xl`, `lg`, `md`, or `sm`. The larger sizes get a glow halo, and `xl` cities also get a static ring and an outward ping.
4. Write the SVG with its CSS animations embedded, because an `<img>`-referenced SVG can't be styled by the page. Every animation delay is negative so dots start mid-cycle and out of phase.

To change the cities, edit `cities` in the script, rerun it, and commit the SVG. The script needs network access and the `d3-geo` and `topojson-client` packages from `package.json`.

## School-management fixture

`tools/testing/schools/` renders the dashboard school-management components against an Axios fixture adapter at `http://127.0.0.1:5187`. There is no authentication, no production network access, and no database write. It's outside every production build.

Use it to check UI behavior: deactivation previews, filters, provenance display, and the disabled community selector for geocoded schools. It doesn't test SQL policy or real Mapbox rendering. The pure-logic tests for the same module run with `pnpm test:schools` (`src/lib/school-management.test.ts`). For the API side, see [Communities and schools admin](/engineering/domains/communities-and-schools-admin).

## Cloudflare worker scripts

Each worker has `check`, `dev`, and `deploy` package scripts that wrap `wrangler`. The **Workers** GitHub Actions workflow runs every `check` on pull requests and deploys changed workers on merge to `main`, so you rarely need the `deploy` scripts. See [Cloudflare Workers](/engineering/ci/release-pipelines#cloudflare-workers).

| Worker | Check | Dev | Deploy | Tests |
| --- | --- | --- | --- | --- |
| `world-cup-router` | `pnpm worker:world-cup:check` | `pnpm worker:world-cup:dev` | `pnpm worker:world-cup:deploy` | `pnpm test:world-cup-router` |
| `experience-router` | `pnpm worker:experience-router:check` | `pnpm worker:experience-router:dev` | `pnpm worker:experience-router:deploy` | `pnpm test:experience-router` |
| `og` | `pnpm worker:og:check` | `pnpm worker:og:dev` | `pnpm worker:og:deploy` | `pnpm test:og` |

`check` verifies the generated `worker-configuration.d.ts` is current (router workers only), typechecks the worker, and runs `wrangler deploy --dry-run`. Run it before you consider any worker change done. It catches bundle-size and binding errors that `tsc` alone can't. For what each worker does, see [Edge and routing](/engineering/web/edge-and-routing).

### Smoke-testing the og worker in workerd

`pnpm test:og` runs satori in Node, which can hide a dependency that fails only in the Workers runtime. Before you change `og` dependencies, run the same smoke test CI runs:

```bash
./scripts/og-worker-smoke.sh
```

The script starts `wrangler dev` on port `8799` (override with `OG_SMOKE_PORT`) with a throwaway signing secret, signs six invite card URLs through `/og/_sign`, and fetches them at the same time. Concurrent requests to a cold isolate are what expose a lazily initialized WASM module. On failure it prints the `wrangler dev` log and exits `1`.

Keep `satori` below `0.33`. Version 0.33 loads harfbuzzjs, which crashes `yelo-og` at startup on Workers. `package.json` pins `^0.32.0` and Dependabot ignores `>=0.33.0`.

### Deploying a worker

Merging to `main` deploys every worker whose own directory changed. A change to only `package.json` or `pnpm-lock.yaml` is verified but not deployed. To ship it, open **Actions → Workers → Run workflow** in `yelo-web` and pick the worker. `pnpm worker:<name>:deploy` still works from a machine logged in to Wrangler.
