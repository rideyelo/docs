---
title: "Enums and value sets"
description: "Every Postgres enum type in the yelo-api schema, which ones are still used, the CHECK-constrained text columns that act as enums, and the Go constants that mirror them, including where Go and the database disagree."
---

The schema has five Postgres `ENUM` types, and only two are attached to columns. Most enumerated values are `text` columns, either guarded by a `CHECK (col = ANY (ARRAY[...]))` constraint or not constrained at all, with the value set defined by Go constants. See [Database overview](/reference/database/overview#enums) for why.

When you add a value:

- For a Postgres enum, `ALTER TYPE ... ADD VALUE` in a migration. It can't run inside a transaction block on older Postgres versions and can't be removed later.
- For a `CHECK` column, drop and re-create the constraint in a migration. Deploy the migration before code that writes the new value, because migrations run before traffic shifts.
- For an unconstrained column, update the Go constants and every SQL literal that filters on the old set.

### RidesStatus

Created in `000001_init_db` as the type of `Rides.status`. Migration `000033_change-ride-status-col-type` converted the column to `text` with `ALTER COLUMN status TYPE text USING status::text`. The type was never dropped.

The Go type `models.RideStatus` (`internal/models/ride.go`) has diverged completely:

| Go constant | Value | In `RidesStatus`? |
| --- | --- | --- |
| `RideStatusRequested` | `requested` | Yes |
| `RideStatusConfirmed` | `confirmed` | Yes |
| `RideStatusQueued` | `queued` | No |
| `RideStatusDriverEnRoute` | `driver_en_route` | No |
| `RideStatusDriverWaiting` | `driver_waiting` | No |
| `RideStatusInProgress` | `in_progress` | Yes |
| `RideStatusPendingRiderRating` | `pending_rider_rating` | No |
| `RideStatusCompleted` | `complete` | Yes |
| `RideStatusNoDriversAvailable` | `no_drivers_available` | No |

`matched` exists only in the enum. No Go code writes it. Cancellation isn't a status; see [Rides](/reference/database/rides#ride-status-model).

### CancelType

Created in `000001_init_db` as the type of `Rides.cancel_type`. Migration `000108_cancel-comment` dropped that column. Cancellation is now described by three text columns on `Rides`:

- `cancel_user`: `rider` or `driver` from `models.UserType` (`UserTypeRider`, `UserTypeDriver`), or `NULL` for system cancellations.
- `cancel_phase`: the `RideStatus` the ride was in when cancelled.
- `cancel_reason`: free text, with the system values `automatic` and `superseded`.

The Go `Ride` struct still tags `CancelUser` with `db:"cancel_type"` and `json:"cancel_type"` (`internal/models/ride.go:176`). The JSON field name leaks the old column name into the API.

### DriverApplicationStatus

Created in `000001_init_db` as the type of `Users.driver_registration_status`. Migration `000030_split-driver-signup-fields` dropped that column. Driver application state now lives in `DriverApplications` as unconstrained text, using `models.ApplicationStatus` (`internal/models/driver.go`):

| Go constant | Value |
| --- | --- |
| `ApplicationStatusNotApplied` | `not_applied` |
| `ApplicationStatusPending` | `pending` |
| `ApplicationStatusComplete` | `complete` |
| `ApplicationStatusFailed` | `failed` |
| `ApplicationStatusRestricted` | `restricted` |
| `ApplicationStatusUnknown` | `unknown` |

None of these match the enum's PascalCase labels.

### kpi_manual_metric

Created in `000221_kpi_manual_log` for `KpiManualLog.metric`, which records manually entered KPI values on the dashboard. Go mirrors it exactly with `models.KpiManualMetric` in `internal/models/kpi.go`: `KpiManualMetricRevenue`, `KpiManualMetricSpotlights`, `KpiManualMetricImpressions`.

### river_job_state

Created by the vendored River migrations `000242_river_v1` through `000248_river_v7`. River's Go library owns the values through `rivertype.JobState`. Yelo SQL references the state in a few places, for example `ClaimRideOperationsWithoutLiveJob` and the Stripe reconciliation dispatcher treat `available`, `pending`, `running`, `retryable`, and `scheduled` as live. Don't alter this type by hand.

## Unconstrained text value sets

These columns have no database constraint. Go constants are the only definition, so a typo in SQL or a new value in Go is accepted silently.

| Column | Values | Go definition |
| --- | --- | --- |
| `Rides.status` | See [RidesStatus](#ridesstatus) | `models.RideStatus` |
| `Rides.vehicle_type` | `x`, `xl`, `cart`, `minibus`. Only `CHECK (vehicle_type <> '')` applies. | `models.VehicleType`. Vehicle types are also configured in `VehicleTypes`. |
| `Rides.cancel_user` | `rider`, `driver`, `NULL` | `models.UserType` |
| `Rides.cancel_phase` | Any `RideStatus` value | `models.RideStatus` |
| `RideEvents.event_type` | 33 values such as `ride_requested`, `ride_accepted`, `payment_confirmed`, `tip_captured`, `rescue_alert_sent` | `models.RideEventType`, `internal/models/ride_event.go` |
| `RideEvents.actor_type` | `rider`, `driver`, `system` | `models.RideEventActorType` |
| `RideNotifications.type` | `no_drivers_available`, `driver_matched`, `driver_arrived`, `completed`, `rider_canceled`, `driver_canceled`, `ride_offered` | `models.RideNotificationType`. Note the American spelling `canceled`. |
| `DriverNotifications.type` | `fare_increase`, `unclaimed_ride`, `unclaimed_ride_recent_only`, `renew_online` | `models.DriverNotificationType`, `internal/models/community.go` |
| `DriverApplications.profile_picture_status`, `license_status`, `stripe_status` | `not_applied` (default), `pending`, `complete`, `failed`, `restricted`, `unknown` | `models.ApplicationStatus` |
| `Fleets.stripe_status` | `not_required` (default), `pending`, `restricted`, `complete` | Literals in `internal/service/payment/payment.go` |
| `Users.gender` | `male`, `female`, `other`, `prefernottosay` | `models.GenderOption` |

<Warning>
Spelling differs across value sets: `AuthTransactions.status` uses `cancelled`, while `RideNotifications.type` uses `rider_canceled` and `driver_canceled`, and `river_job_state` uses `cancelled`. Copy values from the Go constants rather than typing them.
</Warning>
