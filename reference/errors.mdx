This page lists every error type the API can return and what each client does with it. For how the error envelope is built, see [Request lifecycle](/engineering/api/request-lifecycle#error-handling). That page covers the v1 and v2 envelope shapes, `errorHandler` normalization, and responses with a `null` body.

<Note>
API paths are relative to `yelo-api`. Mobile paths are relative to `yelo-frontend`. Web paths are relative to `yelo-web`.
</Note>

## Error model

Every API error is an `errors.Error` (`internal/utilities/errors/error.go:47`). It carries five fields that reach the client.

| Field | v2 envelope key | v1 body key | Source | Notes |
| --- | --- | --- | --- | --- |
| Type | `error.code` | `code` | `GetType()` | The machine-readable code. Clients key off this. |
| Message | `error.message` | `error` | `Error()` | Internal message. `errors.Wrap` prefixes it with context, so it can contain wrapped causes. |
| Title | `error.title` | `title` | `Title()` | User-facing heading. |
| Body | `error.body` | `body` | `Body()` | User-facing sentence. |
| Fingerprint | `error.fingerprint` | Not sent | `Fingerprint()` | SHA-256 of type plus message. `ServerError` hashes the first three stack lines instead (`error.go:104`). |

Handler errors always use the v2 envelope. Middleware errors use v2 only when the request sends `X-Api-Version: v2` (`internal/utilities/json/json.go:105`). The mobile app's main Axios client doesn't send that header, so mobile sees v1 bodies for middleware errors, including `AccountDeletedError` and `AccountBannedError`.

<Warning>
`error.message` is not safe to show users. `NewServerErrorFromError(err)` uses the raw Go error as the message (`error.go:169`). A 500 can therefore expose driver or SQL error text in `message`. Show `body` or `title` instead.
</Warning>

### Constructors

| Constructor | Type | Default title | Default body |
| --- | --- | --- | --- |
| `NewServerError`, `NewServerErrorFromError`, `Wrap` of a non-`errors.Error` | `ServerError` | Something Went Wrong | Oops! Something didn't go as planned. Try again, or come back later. |
| `NewBadRequestError` | `InputError` | Something Went Wrong | Oops! Something didn't go as planned. Try again, or come back later. |
| `NewUnauthorizedError` | `UnauthorizedError` | Unauthorized | You are not authorized to access this resource. |
| `NewForbiddenError` | `ForbiddenError` | Access Denied | You are not authorized to access this resource. |
| `NewNotFoundError` | `NotFoundError` | Not Found | The resource you are looking for could not be found. |
| `NewError(message, type, title, body)` | Any | Caller-supplied | Caller-supplied |
| `NewErrorWithCause` | Any | Caller-supplied | Caller-supplied. The cause is kept for `errors.Is` but not included in `Error()`. |

`errors.Wrap` keeps the wrapped error's type, title, body, and fingerprint. It only prefixes the message.

### Responses without an error body

| Status | When | Source |
| --- | --- | --- |
| 401 | The user lacks the required role | `getRequireRoleMiddleware` |
| 401 | The auth cache lookup fails, for example a Redis or Postgres error | `internal/server/http/middleware.go:266` |
| 401 | The Clerk token is missing or invalid, or the dashboard scope check fails | `internal/server/http/clerk_middleware.go:56`, `:88` |
| 403 | The Clerk role gate fails | `clerk_middleware.go:97` |
| 429 | The per-IP token bucket rejects the request | `middleware.go:196` |

## Auth v3 error codes

Auth v3 reports errors through two channels. JSON endpoints return the v2 envelope with the `ErrorType` as `error.code`. Browser callbacks redirect to the client's `redirect_uri` with `?error=<code>&state=...&request_id=...` (`internal/server/http/authv3/handler.go:1015`). `stableCallbackError` (`handler.go:1111`) collapses the type to a small public set.

| `ErrorType` | Callback `error` value |
| --- | --- |
| `IdentityConflictError` | `identity_conflict` |
| `AccountMergeRequiredError` | `account_merge_required` |
| `ExistingAccountVerificationRequiredError` | `verify_existing_account` |
| `AuthTransactionExpiredError` | `transaction_expired` |
| `ProviderUnavailableError`, `AuthV3UnavailableError` | `temporarily_unavailable` |
| Anything else | `authentication_failed` |

The hosted web flow can also send the app `error=web_recovery` (`yelo-web/src/sites/signup/auth-v3/redirects.ts:36`).

### Phone verification outcomes

`POST /authv3/providers/phone/send` and `/verify` return an `outcome` field rather than an error for expected results (`internal/service/authv3/phone/policy.go:29`).

| Outcome | Meaning |
| --- | --- |
| `sent` | Code sent |
| `verified` | Code accepted |
| `invalid` | Wrong code or undeliverable number |
| `expired` | Code expired |
| `rate_limited` | Provider or Yelo limit hit |
| `provider_unavailable` | Twilio unavailable |

When the phone step fails as an error instead, the service returns `InputError` with one of these titles (`internal/service/authv3/phone_orchestration.go:511`):

| Title | Body |
| --- | --- |
| Wrong Code | That code didn't match. Check it and try again, or request a new one. |
| Can't Text That Number | That number can't receive verification codes. Check it and try again. |
| Code Expired | That code expired. Request a new one to continue. |

### Retry-After

Auth v2 and v3 rate-limit responses set `Retry-After` as an HTTP date (`internal/server/http/authv3/handler.go:855`, `internal/server/http/authv2/handler.go:127`). CORS exposes the header on `/authv3` routes. The per-IP limiter never sets it.

## Validation errors

`validator.ErrorOrNil` joins every failed check into one string in the form `key: message, key: message`. It uses that string as both `message` and `body`, with the title `Oh no!` (`internal/utilities/validator/validator.go:47`). There is no per-field array. Clients that need field-level errors must parse the string.

Fuego struct-tag failures and JSON decode failures become `InputError` with Fuego's `Detail` as the message and the generic "Something Went Wrong" title and body (`internal/server/http/middleware_error.go:30`).

### Auth v3 client

`lib/auth/client.ts` sends `X-API-Version: v2` with a 15-second timeout. It normalizes envelope codes to the callback codes (`client.ts:81`), so one set of checks covers both channels. Network failures become synthetic codes: `request_timeout`, `network_unavailable`, or `invalid_server_response`. A non-envelope HTTP error becomes `http_<status>`.

| Condition | Where | Behavior |
| --- | --- | --- |
| Code is `identity_conflict`, `account_merge_required`, `verify_existing_account`, `transaction_expired`, `temporarily_unavailable`, or `authentication_failed` | `client.ts:107` (`isAuthV3Terminal`) | Leaves the current step and shows the typed error screen |
| 503, `http_503`, or `temporarily_unavailable` | `client.ts:111` (`isAuthV3Unavailable`) | The error screen offers the hosted web flow (`app/(auth-v3)/error.tsx:15`) |
| `transaction_expired`, 410, 401, `http_401`, or `UnauthorizedError` | `providers/AuthV3Provider.tsx:188` | Starts a fresh transaction transparently |
| 429 on phone send or verify | `client.ts:222`, `client.ts:65` | Parses `Retry-After` and shows "Too many attempts. Try again in N seconds." |
| Any `?error=` on the callback URL | `lib/auth/security.ts:183` | Throws `callback_error`. The specific code is discarded. |

## Retry behavior

| Client | Scope | Retries | Backoff | Never retried |
| --- | --- | --- | --- | --- |
| API | `NewCriticalRetrier` (payments, confirmations) | 3 attempts | Full jitter, 100 ms base, 5 s max | Types marked "No" in the [catalog](#error-catalog) |
| API | `NewNetworkRetrier` (provider calls) | 5 attempts | Full jitter, 200 ms base, 10 s max | Same, unless a provider-specific `RetryIf` is passed |
| API | Analytics retrier | 2 attempts | 50 ms base, 2 s max | Same |
| Mobile | React Query default (`app/_layout.tsx:127`) | 3 retries | React Query default | 401, 403 |
| Mobile | `useCurrentUser` (`api/helpers/authUser.ts:67`) | 3 retries | `min(1000 × 2^n, 10000)` ms | 401 |
| Mobile | Community feed, map feed, feed card (`api/helpers/community.ts:232`, `providers/MapFeedProvider.tsx:130`, `components/map/feed/MapFeedCard.tsx:176`) | 3 retries | Default | 400 only |

| Mobile | Fleet join preview and profile accounts | 1 retry | Default | None |
| Mobile | Ride matching screen, bump preview, POI details | None | None | Everything |
| Mobile | Contact match upload (`lib/contacts/contactMatchRetry.ts:30`) | 3 attempts | `min(750 × 2^n, 4000)` ms plus 0 to 250 ms jitter | 429 and other 4xx. Retries network errors and 5xx only. |
