This page lists every PostHog event in the API (Go), the web signup site, and the mobile app, and shows where each one fires in code. For SDK setup, E2E disabling, and the high-level masking rules, see [Observability](/engineering/observability).

<Note>
Source paths are relative to each repository root: `yelo-api`, `yelo-web`, and `yelo-frontend`. Line numbers point to the capture call, or to the hook call site for mobile events.
</Note>

## API business events

The API sends events to PostHog in two ways:

- **Metrics provider.** `PostHogMetricsProvider` in `internal/utilities/metrics/posthog.go` turns `IncrementCounter`, `RecordHistogram`, and `SetGauge` calls into captures. It drops names that start with `http.`, `db.`, `external.`, `system.`, `redis.`, `circuit.`, `rate.`, or `runtime.` (`isBusinessMetric`, line 222). `cmd/api/main.go:175` wires it into `MultiMetricsProvider` only when `cfg.Telemetry.OtelEnabled` is true. Otherwise the API uses `NoOpMetricsProvider` and sends no business events.
- **Direct client.** `AuthV2Service.captureEvent` (`internal/service/authv2/authv2.go:189`) calls `posthog.Enqueue` directly. It skips the metrics provider and the `OtelEnabled` gate.

Every other `IncrementCounter`, `RecordHistogram`, or `SetGauge` call in `internal/` uses a dropped prefix (`http.server.*`, `db.pool.*`, `rate.limiter.*`). Right now `authv3.step` is the only metric that reaches PostHog.

### Unused API capture paths

- `Logger.CaptureError` (`internal/utilities/logger/posthog.go:12`) would capture an event named after the error message, with `method`, `path`, and `trace`. Nothing calls it.
- `PostHogMetricsProvider.RecordError` (`posthog.go:152`) is a no-op. Its comment says `logger.ErrorC` already sends errors to PostHog, but `ErrorC` only reports to Sentry.

## Web (signup Auth v3)

Only `src/sites/signup/auth-v3/analytics.ts` imports `posthog-js`. Nothing else in `yelo-web/src` captures events. Every event goes through `captureAuthV3Event` (line 200) or `captureAuthV3Abandonment` (line 211). Both return early unless capture is enabled.

Capture is enabled only when all of these hold (`shouldCaptureAuthV3`, line 104):

- `VITE_POSTHOG_KEY` is set.
- The environment is `production`.
- The context is not an emulator or a test account (`is_test` comes from the API's `analyticsExcluded` flag).
- The context email does not end in `@rideyelo.com`.

If a later context update makes capture disallowed, `updateAuthV3AnalyticsContext` stops session recording and turns capture off.

Every event carries `stage`, `operation`, and `outcome`, plus the safe context: `attempt_id`, `transaction_id`, `request_id`, `client_id`, `channel`, `distribution`, `app_version`, `app_build`, `is_emulator`, `is_test`. ## Mobile

Mobile events go through the `EventRecorder` interface (`lib/analytics/types.ts`). Its PostHog implementation is `lib/analytics/recorder/posthog.ts`. Hooks in `lib/analytics/events/` call `analytics.track`. Auth v3 events use `trackAuthV3` in `lib/auth/analytics.ts:170`. A few screens call `usePostHog().capture` directly.

## Group analytics

Only the mobile app uses groups. It uses one group type, `community`, keyed by community ID, with no group properties:

- `api/helpers/authUser.ts:110` sets it after identify when `user.community_id` is present.
- `app/(app)/profile/community-switch.tsx:146` sets it after a community switch.

The API and web client never call `group` or `GroupIdentify`.

### Redaction and exclusion

- **Web email.** The context can hold `email` only to check the `@rideyelo.com` exclusion. `persist`, `safeAuthV3EventContext`, and `register` (`analytics.ts:138`, `:194`, `:191`) strip it. Query parameters are cut down to an allowlist by `sanitizedAuthV3Search` (`:121`).
- **API Auth v2.** Phone and email go through `phone.MaskPhone` and `maskEmail` before they are used as properties or distinct IDs.
- **API funnel.** `SetFunnelProperty` only accepts bounded values. `recordUserClassification` (`internal/service/authv3/telemetry.go:129`) sends `is_internal` but not the email.
- **Mobile Auth v3.** `trackAuthV3` drops events for staging, development, and emulator builds, and for test or `@rideyelo.com` accounts. `safeFailureReason` keeps only `error.code`, capped at 80 characters.
- **Mobile route data.** `withConsentedAggregatorRoute` (`lib/analytics/events/rideAggregator.ts:71`) and `diagnoseProviderRequest` send pickup and dropoff coordinates only when provider diagnostics consent is current.
