## How metrics are exported

`otel.InitializeOTel` (`internal/utilities/otel/otel.go:79`) creates a `MeterProvider` with the OpenTelemetry Prometheus exporter (`go.opentelemetry.io/otel/exporters/prometheus` v0.68.0) whenever `OTEL_ENABLED` is true. `GET /metrics` serves `promhttp.Handler()` (`mountObservability`, `internal/server/http/middleware_metrics_auth.go:22`), mounted only when `METRICS_AUTH_TOKEN` is set, which reads the default Prometheus registry.

The exporter uses its default `UnderscoreEscapingWithSuffixes` strategy, so OpenTelemetry names change on export:

| Rule | OpenTelemetry | Prometheus |
| --- | --- | --- |
| Dots become underscores | `redis.cache.hit` | `redis_cache_hit_total` |
| Counters get `_total` | `rate.limiter.rejected` | `rate_limiter_rejected_total` |
| Units become suffixes | `s`, `By`, `ms` | `_seconds`, `_bytes`, `_milliseconds` |
| Curly-brace units are dropped | `{request}` | No suffix |
| Histograms expand | `redis.operation.duration` (unit `s`) | `redis_operation_duration_seconds_bucket`, `_sum`, `_count` |
| Label dots become underscores | `http.route` | `http_route` |

The default registry also exposes a `target_info` series with resource attributes, plus the `go_*` and `process_*` collectors that `client_golang` registers by default.

### Providers

`cmd/api/main.go:168` builds a `MultiMetricsProvider` with two backends when `OTEL_ENABLED` is true:

- `OtelMetricsProvider` (`internal/utilities/metrics/otel.go`) records everything below.
- `PostHogMetricsProvider` (`internal/utilities/metrics/posthog.go`) forwards only `IncrementCounter`, `RecordHistogram`, and `SetGauge` calls whose name doesn't start with `http.`, `db.`, `external.`, `system.`, `redis.`, `circuit.`, `rate.`, or `runtime.` (`posthog.go:222`). Today that's only `authv3.step`. The `auth.v2.*` events go to the PostHog client directly and don't pass through this provider.

When `OTEL_ENABLED` is false, both backends are replaced by `NoOpMetricsProvider`, which also stops `authv3.step` from reaching PostHog. Direct `auth.v2.*` captures are unaffected.

### Label cardinality

- `http.route` is always the raw URL path, so every ride, user, or community ID creates a new series. Requests that match no route are answered by `http.ServeMux` before any Fuego middleware runs, so they aren't recorded at all.
- `error.fingerprint` on `error.count` is a hash of the message for non-server errors. Messages that embed IDs or wrapped causes create a new series per unique message.
- `notification.type` is the template code, which admins create.

## Dashboard KPI definitions

[Ride metrics](/dashboard/ride-metrics) defines Ride Requests, Confirmed Requests, Completed Rides, Completion Rate, Cancelled Rides, and Uncompleted Rides. This section covers the queries and the remaining cards. All queries are in `internal/data/repository/queries/analytics.sql`.

### Shared predicates

| Predicate | SQL |
| --- | --- |
| Counted user | `u.is_deleted = FALSE AND profile_completed AND NOT auth_v3_provisional AND NOT u.is_test` |
| Counted driver | Counted user joined to `"DriverApplications"` with `da.is_active = TRUE` |
| Completed ride | `status IN ('complete', 'pending_rider_rating') AND cancel_phase IS NULL` |
| Ride fare | `COALESCE(discounted_price, price)` |
| Test markets | Global queries also require `NOT c.is_test` on the user's or ride's community |
| Time bucket | Rides use `request_time`. Users use `COALESCE(UserAttribution.profile_completed_at, created_timestamp)`. Drivers use `COALESCE(da.activated_at, created_timestamp)`. Attenders use `EventAttendees.created_at`. |

### Community overview and fleet overview

`GET /dashboard/{id}/kpis` (`community.GetMarketKPIs`) runs `GetDashboardMarketMetrics`. `GET /dashboard/fleet/{fleet_id}/kpis` (`fleet.GetFleetKPIs`) runs `GetDashboardFleetMetrics`. The `range` query parameter is `last_7_days` (default), `last_14_days`, or `last_30_days`. The prior period is the window of the same length immediately before (`internal/service/dashboard/dashboard.go:178`). Ride counts use a half-open window: `request_time >= start AND request_time < end`.

| Card | Field | Definition |
| --- | --- | --- |
| **Active Users** | `users` | Counted users in the community whose profile completion time is before the window end. A running total, not a period count. |
| **Active Drivers** | `drivers` | Counted drivers in the community activated before the window end |
| **Ride Searches** | `RideSearches` | Rows in `"LocationSearches"` for the community in the window (`CountDashboardSearches`) |
| **Total Earnings** (fleet) | `earnings + qr_payment_earnings` | `SUM(driver_payout)` for completed fleet rides, plus `SUM(amount_total) / 100` for fleet `"QrPayments"` not marked `unpaid` |
| **Market Users** (fleet) | `market_users` | Counted users in the fleet's community before the window end |
| **QR Payments** (fleet) | `qr_payment_count` | Fleet `"QrPayments"` created in the window, excluding `unpaid` |

Each card's delta is `current - previous`. `PercentageChange` is `delta / previous × 100`, rounded to two decimals. When the previous value is 0 and the current value is positive, it's reported as 100 (`dashboard.go:161`).

### Global KPIs

`GET /dashboard/kpi/global` (`dashboard.GetGlobalKPIs`) runs `GetGlobalKPITotals` three times: all time, the current ISO week from Monday 00:00 UTC to now, and the previous full week (`internal/service/dashboard/kpi.go:31`). The card value is the all-time total. The delta compares this week with last week. When last week is 0, `PercentageChange` is 0.

| Card | Definition |
| --- | --- |
| **Total Users** | Counted users in non-test communities |
| **Total Drivers** | Distinct counted drivers in non-test communities |
| **GMV** | Sum of ride fare for completed rides in non-test communities |
| **Attenders** | Distinct counted users in `"EventAttendees"` |
| **Completed Rides** | Completed rides in non-test communities |

`ListWeeklyKPISeries` returns 12 weeks (`kpiSeriesWeeks`) bucketed by `date_trunc('week', ...)` with the same predicates.

### Signup acquisition

`GET /dashboard/kpi/acquisition` runs `ListKPIAcquisitionChannels`. Each counted user gets exactly one source from the first rule that matches, in this order:

| Order | Source | Rule |
| --- | --- | --- |
| 1 | `world_cup` | First touch `landing_surface` contains "world" then "cup" |
| 2 | `driver_page` | `landing_surface` or `referrer_path` contains "driver" |
| 3 | `invite_link` | Touch has a `referral_code` |
| 4 | `join_link` | `landing_surface` or `referrer_path` contains "join", or `source_channel` contains "community" |
| 5 | `dub` | Touch has a `dub_click_id` |
| 6 | `utm:<source>` | Touch has a `utm_source` |
| 7 | `<source_channel>` | Touch has a `source_channel` |
| 8 | `web` | `landing_surface` is `web` or `/auth/v3` |
| 9 | `app` | `landing_surface` is `app`, `ios`, `android`, or `native` |
| 10 | `invite_link` | A `"Referrals"` row names the user as referee |
| 11 | `self_reported:<source>` | Earliest non-empty `referral_sources.source`, slugified |
| 12 | `<channel>` | Channel of the first verified or completed sign-in `"AuthTransactions"` row from 5 minutes before to 24 hours after signup |
| 13 | `invite_link`, `app`, `join_link`, or the raw value | Legacy `Users.acquisition_source`: `app_referral`, `app_organic`, `event_link`, or anything else |
| 14 | `legacy_unattributed` | User created before the first `"AttributionTouches"` row |
| 15 | `unknown` | Nothing matched |

The touch is the user's `first_touch_id`, then `last_touch_id`, then their earliest touch.
