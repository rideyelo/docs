Use these terms exactly in tickets, specs, and code reviews. Each entry links to the page that covers it in depth.

## People and roles

| Term | Definition |
| --- | --- |
| **Rider** | A user who requests rides in the mobile app. |
| **Driver** | A user who completed driver onboarding and fulfills rides. A user can be both a rider and a driver, but not active as both at once. |
| **Fleet manager** | An external operator with dashboard access scoped to their fleet. See [Dashboard roles](/administration/dashboard-roles). |
| **Admin** / **Intern** | Internal dashboard roles. Admins have full access. Interns have a reduced set of pages. |
| **Owner-operator** | A fleet payment model where drivers are paid on their own Stripe account instead of the fleet's. See [Fleets](/concepts/fleets). |

## Markets

| Term | Definition |
| --- | --- |
| **Community** | A market, usually one school. It scopes matching, pricing, vehicle types, and operating hours. Users are assigned to a community by location. See [Communities and zones](/concepts/communities-and-zones). |
| **School** | A record for an academic institution. Schools map to communities but don't move users between them. |
| **Zone** | A polygon inside a community used for pricing and map display. |
| **Operating hours** | When a community is `LIVE` or `OFF_PEAK`. See [Operating hours](/admin/operating-hours). |
| **Fleet** | A third-party operator that runs drivers in one or more communities. Payouts go to the fleet or to the driver, depending on the payment model. |

## Rides

| Term | Definition |
| --- | --- |
| **Ride** | One trip from pickup to dropoff. It has a status, fare, driver, and payment intent. See [Ride lifecycle](/concepts/ride-lifecycle). |
| **Drive** | A driver's view of a ride they accepted. It's the same ride record with a different UI. |
| **Quote** | The fare shown for each vehicle type before the rider confirms. Confirm reprices the ride, so the stored fare can differ slightly from the quote. See [Pricing](/concepts/pricing). |
| **Ride board** | The per-community set of `confirmed` rides waiting for a driver. |
| **Auto-queue** | A driver mode where Yelo assigns rides to the driver's queue instead of the driver picking from the ride board. See [Matching and auto-queue](/concepts/matching-and-auto-queue). |
| **Requeue** | Putting a ride back on the ride board, for example when a driver cancels before pickup. |
| **Confirm code** | The 4-digit code the rider shows the driver to confirm pickup. |
| **Cancel phase** | The status a ride was in when it was cancelled or expired. Cancelled and expired rides end in `complete` with `cancel_phase` and `cancel_reason` set. See [Cancellations](/concepts/cancellations). |
| **User status** | A server-owned field (`riding` or `driving`) that decides which mode the mobile app shows. |
| **Heartbeat** | A periodic request from logged-in clients with location and device state. It powers presence and online counts. |

## Money

| Term | Definition |
| --- | --- |
| **Jitter** | A small random amount added to computed fares so prices don't look fixed. |
| **Anchor price** | The higher "was" price displayed next to the actual fare. |
| **Surge** | A community-level fare multiplier with an expiry time. |
| **Payment intent** | The Stripe authorization created when a driver accepts a ride, on the driver's or fleet's connected account. See [Payments and payouts](/concepts/payments-and-payouts). |
| **Tip window** | The 24 hours after a ride completes during which the rider can tip. For tip-enabled rides, capture waits until the rider rates or the window closes. See [Tips and earnings](/concepts/tips-and-earnings). |
| **QR payment** | A fleet payment link, reached by QR code, for fixed or custom amounts. See [QR payments](/dashboard/qr-payments). |

## Engineering

| Term | Definition |
| --- | --- |
| **Auth v3** | The current sign-in system for mobile and web, with Apple, Google, and phone sign-in. See [Authentication](/engineering/api/authentication). |
| **Onboarding token** | A short-lived token issued mid-sign-in, before the account is complete. Most endpoints reject it. |
| **River** | The Postgres-backed job queue the API uses for durable background work. See [Background jobs](/engineering/api/background-jobs). |
| **OTA update** | A JavaScript-only mobile update shipped through EAS Update. It can't change native code or permissions. See [Mobile releases](/engineering/mobile/releases). |
| **Native build** | A full iOS or Android build submitted to the stores. Required for native code, permissions, and plugin changes. |
| **Generated client** | Orval-generated API hooks in `yelo-web` and `yelo-frontend`. Never edit them by hand. See [OpenAPI and generated clients](/engineering/openapi-and-clients). |
